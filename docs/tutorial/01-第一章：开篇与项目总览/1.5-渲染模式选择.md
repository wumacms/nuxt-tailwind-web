# 1.5-渲染模式选择

**【录屏提示】** 开场：讲师出镜，背景为 SSR / SSG / SPA 三个词。

---

## 一、开场白（约 30 秒）

好，欢迎回来。

这一节我们讲一个**企业站必须想清楚**的问题：**渲染模式怎么选？**

Nuxt 支持好几种渲染模式——SSR、SSG、SPA，还有混合渲染。很多同学第一次接触会懵：到底该用哪个？

更麻烦的是，**不同的页面可能需要不同的模式**。比如首页要快、要 SEO，后台要强交互、不需要 SEO。

这一节，我们把这件事讲透。学完之后，你能给项目的每个页面**做出有依据的选择**。

---

## 二、三种基础模式（约 4 分钟）

我们先讲三种基础模式。

**【录屏提示】** 屏幕显示三种模式的流程图。

**第一种，SSR——服务端渲染。**

它的流程是：用户请求 → 服务器执行 Vue 代码 → 生成完整 HTML → 返回给浏览器。

**优点**：首屏快，SEO 好。因为用户拿到的是渲染好的 HTML。

**缺点**：服务器有压力。每次请求都要执行一遍渲染。而且开发时要注意"服务端没有 `window`、`document`"这个问题。

**适合**：内容频繁变化、需要 SEO 的页面。比如新闻详情、产品详情。

**第二种，SSG——静态站点生成。**

它的流程是：**构建时**就把所有页面渲染成 HTML 文件，部署到 CDN。

**优点**：最快。因为用户拿到的是纯静态文件，CDN 直接返回，服务器零压力。

**缺点**：内容更新需要重新构建。不适合频繁变化的内容。

**适合**：内容相对固定的页面。比如首页、关于我们、联系我们。

**第三种，SPA——单页应用。**

就是我们熟悉的 Vue 默认模式。服务器只返回一个空 HTML，所有渲染在浏览器里完成。

**优点**：交互流畅，服务器压力小。开发简单，不用考虑服务端环境。

**缺点**：首屏慢，SEO 差。

**适合**：登录后的后台系统、强交互的应用。

**【录屏提示】** 镜头切回讲师。

我做个总结：**看三个维度——内容变化频率、SEO 需求、交互复杂度。**

- 内容固定 + 要 SEO → SSG
- 内容常变 + 要 SEO → SSR
- 强交互 + 不要 SEO → SPA

## 三、Nuxt 的混合渲染（约 3 分钟）

好，但真实项目往往是**混合的**。首页要 SSG，产品详情要 SSR，后台要 SPA。

Nuxt 提供了 **`routeRules`** 来支持这种混合渲染。

**【录屏提示】** 打开 `nuxt.config.ts`。

我们看怎么写：

```ts
export default defineNuxtConfig({
  routeRules: {
    '/': { prerender: true },
    '/about': { prerender: true },
    '/products/**': { swr: 3600 },
    '/news/**': { isr: 3600 },
    '/admin/**': { ssr: false },
  },
})
```

我们一条条看。

`'/'` 和 `'/about'` 用 `prerender: true`，意思是**构建时就生成静态 HTML**，对应 SSG。

`'/products/**'` 用 `swr: 3600`，意思是**缓存 3600 秒**，期间用户拿到缓存，过期后后台更新。这叫"陈旧内容优先"。

`'/news/**'` 用 `isr: 3600`，增量静态再生。和 swr 类似，但行为略有不同——ISR 是过期的**第一个**用户触发更新，SWR 是后台异步更新。

`'/admin/**'` 用 `ssr: false`，意思是**这个路径下的页面走 SPA 模式**，不做服务端渲染。

**【录屏提示】** 镜头拉近，语气放慢。

**这就是混合渲染的威力**：一个项目，不同路径用不同策略，各取所长。

你不需要全站 SSR，也不需要全站 SPA。**按页面特性做选择。**

---

## 四、我们项目的策略（约 1 分 30 秒）

好，那我们这个企业站，具体怎么定？

**【录屏提示】** 屏幕显示策略表。

我给出的方案是：

| 路径            | 模式 | 理由                     |
| --------------- | ---- | ------------------------ |
| `/` 首页        | SSG  | 内容固定，追求最快       |
| `/about` 关于   | SSG  | 内容固定                 |
| `/products/**`  | SWR  | 产品会更新，但不需要实时 |
| `/news/**`      | ISR  | 新闻会更新，时效性中等   |
| `/contact` 联系 | SSR  | 表单需要服务端处理       |
| `/admin/**`     | SPA  | 后台强交互，不需要 SEO   |
| 404 等          | SSG  | 静态错误页               |

**【录屏提示】** 镜头切回讲师。

注意，**这不是唯一正确答案**。如果你的产品数据是每天更新的，用 SSG 也行。如果你的新闻是实时的，那就用 SSR。

**关键是你要理解每种模式的取舍，然后按业务特性做决定。**

## 五、几个注意点（约 1 分钟）

最后讲几个实战注意点。

**【录屏提示】** 屏幕显示注意事项。

**第一，SSR 环境下没有 `window`、`document`、`localStorage`。** 如果你在组件顶层直接访问它们，会报错。要用 `onMounted` 包裹，或者用 `import.meta.client` 判断。

**第二，SSG 时，动态路由需要提供所有可能的路由。** 比如产品详情页，你要在构建时告诉 Nuxt 有哪些产品 slug。这个后面第六章会讲。

**第三，SWR 和 ISR 都需要部署环境支持。** 如果你部署到纯静态托管，这两个用不了。要么用 Node 服务，要么用支持边缘渲染的平台。

**第四，开发时默认走 SSR，但你可以用 `ssr: false` 临时切换。** 调试时很有用。
