## 二、Nuxt 的价值：企业站的三个刚需（约 4 分钟）

我们先说 Nuxt。

**【录屏提示】** 屏幕切到对比画面：左边是 SPA 的网页源码，右边是 SSR 的网页源码。

很多人对 Nuxt 的理解是"Vue 的全家桶框架"，觉得它只是帮你配好了路由和状态管理。这个理解不全对。

Nuxt 对企业站真正的价值，是**三个刚需**。

**第一个刚需：SEO。**

我给大家看一个对比。这是一个用纯 Vue3 SPA 做的企业站，我右键查看网页源代码。

**【录屏提示】** 打开 SPA 站点，查看源代码，展示空白的 `<div id="app">`。

你看，源码里只有一个空的 div，所有内容都是 JS 渲染出来的。搜索引擎爬虫来抓的时候，**它可能什么都抓不到**。

我们再看看 Nuxt SSR 的站点。

**【录屏提示】** 打开 Nuxt SSR 站点，查看源代码，展示完整 HTML。

你看，源码里是完整的 HTML，标题、内容、链接，全都在。搜索引擎一看就懂。

对**企业官网**来说，这是致命的差别。因为企业站的流量，很大一部分来自搜索引擎。你做得再漂亮，搜不到，等于零。

**第二个刚需：首屏速度。**

SPA 的加载流程是：下载 HTML → 下载 JS → 执行 JS → 渲染页面。用户会看到一段时间的白屏。

SSR 是：服务器直接返回渲染好的 HTML，用户立刻能看到内容。

**【录屏提示】** 用 Network 面板对比两者的首屏时间。

对企业站来说，**首屏速度直接影响转化率**。用户等三秒还没看到东西，就关掉了。

**第三个刚需：约定优于配置。**

Nuxt 有一套约定式的目录结构。`pages/` 下的文件自动变成路由，`components/` 下的组件自动导入，`layouts/` 下的布局自动可用。

这意味着**团队协作时，大家不用争论"文件该放哪"**。新人进来，一看目录就懂。这对企业项目的长期维护非常重要。

**【录屏提示】** 镜头切回讲师。

那 Nuxt 是不是万能的？**不是。**

如果你做的是**纯后台管理系统**，用户登录后才能用，不需要 SEO，强交互为主——那用纯 Vue3 SPA 反而更简单，Nuxt 的 SSR 能力你用不上，还增加了复杂度。

所以选型的关键是：**你的项目需不需要 SEO、需不需要首屏速度、需不需要服务端能力。** 企业官网，三个都需要，所以选 Nuxt。

## 三、TailwindCSS 的价值：设计系统落地（约 3 分钟）

好，第二个技术，TailwindCSS。

**【录屏提示】** 屏幕切到一段传统 CSS 与 Tailwind 的对比代码。

很多人对 Tailwind 的第一印象是"这不就是把 CSS 写在 class 里吗，好乱"。

这个印象可以理解，但它**忽略了 Tailwind 真正的价值**。

Tailwind 的核心不是"少写 CSS"，而是——**它是一套设计系统的约束工具**。

我解释一下。传统的写法里，你可能写 `padding: 13px`、`margin: 17px`、`color: #2563eb`。这些数值是**随意的**，每个人的习惯不同，最后项目里会出现几十种间距、十几种蓝色。

Tailwind 的做法是：**它只提供有限的、成体系的取值**。比如间距只有 4、8、12、16 这些 4 的倍数；颜色有完整的梯度。

**这就逼着你在一个受约束的系统里做设计。** 结果就是全站风格统一，改起来也容易。

**【录屏提示】** 镜头切回讲师。

那为什么选 **V4** 版本？

因为 V4 做了一件很重要的事：**它把主题配置从 JS 搬到了 CSS**。用 `@theme` 指令定义令牌，令牌直接变成 CSS 变量，可以运行时切换。

这对"多主题""暗色模式""多品牌"这些企业需求来说，是巨大的提升。我们第二章会详细讲。

当然，Tailwind 也有**不适合的场景**。比如你要做高度定制的动画、复杂的 3D 效果，那还是要写自定义 CSS。Tailwind 是工具，不是教条。

## 四、TypeScript 的价值：工程约束（约 2 分钟）

好，第三个技术，TypeScript。

**【录屏提示】** 屏幕切到一段带 TS 类型提示的代码，展示 IDE 自动补全。

TS 在企业项目里的价值，我觉得主要两点。

**第一，它把"运行时错误"变成了"编译时错误"。**

比如说，你给按钮组件传了一个不存在的 variant，用 JS 的话，要到用户点的时候才发现样式错了。用 TS 的话，编辑器当场就给你标红。

**第二，它是团队协作的"文档"。**

你看到 `ButtonVariant = 'primary' | 'secondary' | 'danger'`，立刻就知道这个按钮支持哪几种形态。不需要去翻文档，也不需要问同事。

**【录屏提示】** 镜头切回讲师。

那 TS 有没有代价？有。它增加了写代码的前期成本，也增加了学习曲线。

所以我的建议是：**在企业项目里用 TS，尤其是多人协作的项目；如果是个人小项目、快速原型，用 JS 也完全可以。**

## 五、三者的职责边界（约 1 分钟）

好，我们把三个技术串起来，讲一下它们的**职责边界**。

**【录屏提示】** 屏幕显示一张三层结构图。

**Nuxt 负责"框架层"**：路由、渲染、数据获取、SEO、服务端能力。

**TailwindCSS 负责"表现层"**：设计令牌、样式组织、响应式、主题。

**TypeScript 负责"约束层"**：类型定义、接口约束、工程规范。

**它们不是互相替代，而是各管一段。** 这就是为什么这套组合在企业站场景下特别合适。
