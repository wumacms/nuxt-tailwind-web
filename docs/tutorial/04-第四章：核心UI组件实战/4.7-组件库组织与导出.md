## 二、目录回顾（约 2 分钟）

**【录屏提示】** 打开 `components/` 目录，展示完整结构。

我们先回顾一下组件的目录设计。

```text
components/
├── ui/          # 基础 UI：AppButton、AppInput、AppCard...
├── layout/      # 布局：AppContainer、AppHeader、PageSection...
├── sidebar/     # 侧边栏模块
├── sections/    # 页面区块：Hero、FeatureGrid、CTA
└── common/      # 通用：Icon、Logo、Empty
```

**【录屏提示】** 镜头切回讲师。

这个结构我们 1.4 讲过。现在组件都做完了，我们来看看**它是否还合理**。

**我的判断是：合理。** 因为：

- `ui/` 是**不依赖业务**的通用组件，可以跨项目复用。
- `layout/` 是**结构组件**，处理页面骨架。
- `sections/` 是**页面级区块**，通常只在本项目用。
- `common/` 是**杂项**。

**判断标准是：组件的复用范围。** 越通用的越靠上层。

## 三、命名规范（约 2 分 30 秒）

**【录屏提示】** 屏幕显示命名规范清单。

命名规范，我讲**四条**。

**第一，组件名用大驼峰（PascalCase）。**

`AppButton.vue`、`PageSection.vue`。不要用 `app-button.vue`。

**第二，通用组件加 `App` 前缀。**

这是我们课程里的约定。`AppButton`、`AppCard`、`AppModal`。这样在模板里一眼能看出"这是我们的基础组件"，而不是第三方的。

**第三，区块组件用业务名。**

`HeroSection`、`FeatureGrid`、`CTASection`。不加 `App` 前缀，因为它不是通用组件。

**第四，避免和 HTML 标签重名。**

不要做 `Button.vue`、`Card.vue`。虽然 Nuxt 会自动加前缀，但容易混淆。**加 `App` 前缀就避免了这个问题。**

**【录屏提示】** 镜头拉近。

**命名是团队协作的"暗号"。** 规范的命名，让别人不用看代码就知道这是什么。

## 四、自动导入的机制（约 2 分 30 秒）

好，讲 Nuxt 的**自动导入**。

**【录屏提示】** 打开 `nuxt.config.ts`，展示 components 配置。

Nuxt 默认扫描 `components/` 目录，**所有组件自动全局可用**。

但有几个细节。

**第一，嵌套目录会变成前缀。**

`components/ui/AppButton.vue` 会被自动导入为 `<UiAppButton>`。但我们想用 `<AppButton>`，怎么办？

**【录屏提示】** 修改配置。

```ts
export default defineNuxtConfig({
  components: [
    { path: '~/components/ui', pathPrefix: false },
    { path: '~/components/layout', pathPrefix: false },
    { path: '~/components', pathPrefix: true },
  ],
})
```

`pathPrefix: false` 表示**不加目录前缀**。这样 `ui/AppButton.vue` 就能用 `<AppButton>` 了。

**第二，`pathPrefix: true` 时目录名会变成前缀。**

`components/sections/HeroSection.vue` 就是 `<SectionsHeroSection>`。所以我们用 `pathPrefix: false` 更省事。

**第三，避免命名冲突。**

如果两个目录下有同名组件，会冲突。所以我们的**命名规范很重要**——用前缀区分。

**【录屏提示】** 镜头切回讲师。

**自动导入是 Nuxt 的便利，也是陷阱。** 它省了 import，但组件多了之后，**"这个组件从哪来的"会变模糊**。我的建议是：**基础组件用自动导入，业务组件显式 import**，保持可追溯。

## 五、组件清单文档（约 1 分 30 秒）

**【录屏提示】** 屏幕显示一个组件清单表格。

最后我讲一句**前瞻**。

我们这套组件，目前是**项目内**的。如果你的团队有多个项目，可以把它抽成**独立的 npm 包**。

但**不要一开始就抽包**。**先在项目里用，用出痛点，再抽。**
