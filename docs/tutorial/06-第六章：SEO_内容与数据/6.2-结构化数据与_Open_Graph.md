# 6.2-结构化数据与_Open_Graph

**【录屏提示】** 开场：讲师出镜，背景为富媒体搜索结果。

---

## 一、开场白（约 30 秒）

好，欢迎回来。

上一节我们讲了基础的 SEO 元信息。这一节，我们讲**进阶的 SEO**——**结构化数据**和 **Open Graph**。

它们能让你的页面在搜索结果和社交分享里，**显示得更丰富、更吸引人**。这是企业站 SEO 的"加分项"。

---

## 二、什么是结构化数据（约 2 分钟）

**【录屏提示】** 屏幕对比普通搜索结果和富媒体搜索结果。

先看对比。

普通搜索结果：标题 + 描述 + URL。

富媒体搜索结果：可能带**评分星级、价格、库存状态、面包屑导航、FAQ 折叠**。

**【录屏提示】** 镜头切回讲师。

差别在哪？**在于有没有"结构化数据"。**

结构化数据是一段 **JSON-LD** 格式的代码，用 Schema.org 的词汇描述页面内容。搜索引擎读懂了，就能展示更丰富的结果。

**它不直接影响排名，但能提高点击率。** 对企业站来说，这很值。

---

## 三、常用 Schema 类型（约 2 分钟）

**【录屏提示】** 屏幕列出常用类型。

企业站常用的 Schema 类型：

**第一，Organization。** 公司信息。放首页。

**第二，Product。** 产品信息。放产品详情页。

**第三，Article。** 文章信息。放新闻详情页。

**第四，BreadcrumbList。** 面包屑。放所有内页。

**第五，FAQPage。** 常见问答。放 FAQ 页。

**第六，LocalBusiness。** 本地商家。有实体店的企业用。

**【录屏提示】** 镜头切回讲师。

**不用每个都做。** 根据企业站的实际内容选。**首页做 Organization，产品页做 Product，新闻页做 Article，这是最基础的三个。**

---

## 四、实现 Organization（约 2 分 30 秒）

**【录屏提示】** 在 `app.vue` 或首页注入。

```ts
useHead({
  script: [
    {
      type: 'application/ld+json',
      innerHTML: JSON.stringify({
        '@context': 'https://schema.org',
        '@type': 'Organization',
        name: '某某科技',
        url: 'https://example.com',
        logo: 'https://example.com/logo.png',
        description: '专业的企业解决方案提供商',
        contactPoint: {
          '@type': 'ContactPoint',
          telephone: '400-000-0000',
          contactType: 'customer service',
        },
        sameAs: [
          'https://weibo.com/example',
          'https://github.com/example',
        ],
      }),
    },
  ],
})
```

**【录屏提示】** 边写边讲。

几个关键点。

**第一，`@context` 固定是 `https://schema.org`。**

**第二，`@type` 指定类型。** 这里是 `Organization`。

**第三，`sameAs` 是"同一实体"的其他链接。** 社交账号、GitHub 等。**这帮助搜索引擎确认"这些账号都属于同一家公司"。**

**第四，用 `useHead` 注入。** 因为 `useSeoMeta` 只处理 meta，不处理 script。

**【录屏提示】** 镜头拉近。

**这段代码放在 `app.vue` 里，全站生效。** 不需要每个页面重复。

## 五、实现 Product 和 Article（约 2 分 30 秒）

**【录屏提示】** 打开产品详情页，加 Product schema。

```ts
useHead({
  script: [
    {
      type: 'application/ld+json',
      innerHTML: () => JSON.stringify({
        '@context': 'https://schema.org',
        '@type': 'Product',
        name: product.value?.name,
        description: product.value?.summary,
        image: product.value?.cover,
        brand: {
          '@type': 'Brand',
          name: '某某科技',
        },
      }),
    },
  ],
})
```

新闻详情页同理，换成 `Article`：

```ts
{
  '@type': 'Article',
  headline: article.value?.title,
  image: article.value?.cover,
  datePublished: article.value?.date,
  author: {
    '@type': 'Organization',
    name: '某某科技',
  },
}
```

**【录屏提示】** 镜头切回讲师。

**注意我用了函数形式 `() => JSON.stringify(...)`。** 和 SEO 元信息一样，保证数据到位后再求值。

**`datePublished` 很重要。** 新闻类内容，搜索引擎看重时效性。

## 六、Open Graph 与社交分享（约 1 分 30 秒）

**【录屏提示】** 屏幕显示 OG 预览效果。

Open Graph 上一节提过，这里深入讲。

**OG 标签决定"分享出去长什么样"。**

在微信里分享你的页面，会显示：标题、描述、缩略图。**这些都来自 OG 标签。**

**【录屏提示】** 屏幕显示 OG 标签清单。

必备的 OG 标签：

- `og:title` — 分享标题
- `og:description` — 分享描述
- `og:image` — 分享缩略图（**最重要**，建议 1200×630）
- `og:url` — 页面 URL
- `og:type` — 类型（website/article/product）

**【录屏提示】** 镜头切回讲师。

**`og:image` 是重点。** 没有它，分享出来是光秃秃的。企业站最好为**每个重要页面**准备专属的 OG 图。

动态页面可以用产品的封面图。首页可以设计一张品牌图。

**测试工具**：微信有"微信分享调试"，Facebook 有"Sharing Debugger"，都能预览分享效果。
