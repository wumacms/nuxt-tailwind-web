# 3.6-侧边栏与面包屑

**【录屏提示】** 开场：讲师出镜，背景为新闻详情页布局。

---

## 一、开场白（约 30 秒）

好，欢迎回来。

这一节我们做**侧边栏和面包屑**。

它们主要出现在**内容型页面**——比如新闻详情、产品详情。侧边栏放"相关内容"，面包屑告诉用户"你在哪"。

这两个组件都不复杂，但**有几个实战细节**值得讲。

---

## 二、面包屑：用户的位置感（约 2 分 30 秒）

先讲面包屑。

**【录屏提示】** 屏幕显示一个典型面包屑：首页 / 新闻 / 某某文章。

面包屑的作用是**告诉用户当前位置，并提供向上导航**。它对 SEO 也有好处，搜索引擎能理解页面层级。

**【录屏提示】** 新建 `components/common/AppBreadcrumb.vue`。

```vue
<script setup lang="ts">
interface BreadcrumbItem {
  label: string
  to?: string
}

interface Props {
  items: BreadcrumbItem[]
}

defineProps<Props>()
</script>

<template>
  <nav aria-label="面包屑" class="py-4">
    <ol class="flex items-center flex-wrap gap-2 text-sm text-gray-500">
      <li v-for="(item, index) in items" :key="index" class="flex items-center gap-2">
        <NuxtLink
          v-if="item.to"
          :to="item.to"
          class="hover:text-brand-500 transition-colors"
        >
          {{ item.label }}
        </NuxtLink>
        <span v-else class="text-gray-900 font-medium">{{ item.label }}</span>

        <span v-if="index < items.length - 1" class="text-gray-300" aria-hidden="true">
          /
        </span>
      </li>
    </ol>
  </nav>
</template>
```

**【录屏提示】** 边写边讲。

几个关键点。

**第一，数据驱动。** 面包屑的内容通过 `items` prop 传入，组件本身不关心数据从哪来。这是**组件设计的基本原则**——只管展示，不管数据。

**第二，最后一项不带链接。** 因为它是"当前页"，点了没意义。用 `item.to` 是否存在来判断。

**第三，`aria-label="面包屑"` 和 `aria-hidden`。** 无障碍支持，分隔符对屏幕阅读器隐藏。

**第四，`flex-wrap`。** 面包屑太长时能换行，手机上不会溢出。

## 三、面包屑的数据来源（约 1 分 30 秒）

**【录屏提示】** 镜头拉近，语气放慢。

面包屑的数据从哪来？我讲**三种方式**。

**方式一：路由 meta。**

```ts
definePageMeta({
  breadcrumb: [
    { label: '新闻', to: '/news' },
    { label: '某某文章' },
  ],
})
```

**优点**：简单直接。**缺点**：动态内容（比如文章标题）不好处理，因为 meta 是静态的。

**方式二：页面内手动传。**

在页面里根据数据构造 `items`，传给组件。**最灵活**，推荐用于动态页面。

**方式三：根据路由自动生成。**

用 `route.path` 拆分生成。**最省事，但最不灵活**，因为路径段可能不是好的展示文案。

**【录屏提示】** 镜头切回讲师。

**我的建议：动态页面用方式二，静态页面用方式一。** 别用方式三，因为展示文案和 URL 往往不一致。

## 四、侧边栏实现（约 3 分钟）

好，讲侧边栏。

**【录屏提示】** 打开新闻详情页，看布局。

新闻详情页的典型布局是：主内容区 + 右侧边栏。桌面两栏，移动端侧边栏移到下方。

**【录屏提示】** 写布局。

```vue
<template>
  <AppContainer>
    <div class="grid grid-cols-1 lg:grid-cols-3 gap-10 py-10">
      <!-- 主内容 -->
      <article class="lg:col-span-2">
        <slot />
      </article>

      <!-- 侧边栏 -->
      <aside class="lg:col-span-1">
        <div class="lg:sticky lg:top-24 space-y-8">
          <AppSidebarRelated :items="related" />
          <AppSidebarContact />
        </div>
      </aside>
    </div>
  </AppContainer>
</template>
```

**【录屏提示】** 边写边讲。

几个关键点。

**第一，`grid-cols-1 lg:grid-cols-3`。** 手机一列（侧边栏在下面），桌面三列（主内容占 2，侧边栏占 1）。

**第二，`lg:sticky lg:top-24`。** 侧边栏在桌面端**粘性定位**，滚动时跟着走。`top-24` 是避开固定 Header（Header 是 64px，加一点余量）。

**第三，移动端不 sticky。** 因为手机上侧边栏在下方，不需要粘性。

**【录屏提示】** 镜头拉近。

**注意 `sticky` 的生效条件：父元素不能有 `overflow: hidden`。** 这是个经典坑。如果 sticky 不生效，先检查父级。

## 五、侧边栏组件拆分（约 1 分 30 秒）

好，侧边栏里通常有多个模块。我建议**拆成独立组件**。

**【录屏提示】** 展示组件目录。

```text
components/
└── sidebar/
    ├── AppSidebarRelated.vue    # 相关文章
    ├── AppSidebarContact.vue    # 联系方式
    └── AppSidebarTags.vue       # 标签云
```

每个模块独立，页面里按需组合。

**【录屏提示】** 镜头切回讲师。

**这样拆的好处是：侧边栏模块可以复用在不同页面。** 比如"联系方式"模块，新闻页、产品页、案例页都能用。
