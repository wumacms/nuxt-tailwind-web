## 二、什么是"布局级组件"（约 2 分钟）

先定义概念。

**【录屏提示】** 屏幕显示组件分层图。

我们把组件分成四层：

**第一层，基础 UI 组件。** 按钮、输入框、图标。**不关心布局。**

**第二层，布局组件。** 容器、栅格、Header、Footer。**关心结构，不关心内容。**

**第三层，区块组件（Section）。** Hero 区、优势区、CTA 区。**关心内容模式，可复用。**

**第四层，页面。** 组装区块，填充具体内容。

**【录屏提示】** 镜头切回讲师。

**这一节讲的"布局组件化"，主要是第二层和第三层。**

## 三、为什么要用插槽（约 2 分 30 秒）

好，讲核心——**插槽**。

**【录屏提示】** 屏幕显示一个 PageSection 的两种实现方式对比。

假设我们要做一个"页面区块"组件，包含标题、副标题、内容。有两种实现方式。

**方式一：用 props 传内容。**

```vue
<PageSection title="我们的优势" subtitle="为什么选择我们" :items="features" />
```

**方式二：用插槽。**

```vue
<PageSection title="我们的优势" subtitle="为什么选择我们">
  <FeatureGrid :items="features" />
</PageSection>
```

**【录屏提示】** 镜头拉近，语气加重。

**方式二更好。为什么？**

因为方式一，`PageSection` 必须知道 `items` 的结构，还要知道怎么渲染。**它和业务耦合了。**

方式二，`PageSection` 只管"标题 + 副标题 + 一块内容"，**内容长什么样它不关心。** 这就是**解耦**。

**【录屏提示】** 镜头切回讲师。

**插槽是布局组件的灵魂。** 它让组件既有统一的结构，又有灵活的内容。

## 四、实现 PageSection（约 3 分钟）

好，我们来写。

**【录屏提示】** 新建 `components/layout/PageSection.vue`。

```vue
<script setup lang="ts">
interface Props {
  title?: string
  subtitle?: string
  align?: 'left' | 'center'
  spacing?: 'sm' | 'md' | 'lg'
}

const props = withDefaults(defineProps<Props>(), {
  align: 'center',
  spacing: 'md',
})

const spacingClasses = {
  sm: 'py-12',
  md: 'py-20',
  lg: 'py-32',
} as const

const alignClasses = {
  left: 'text-left',
  center: 'text-center mx-auto',
} as const
</script>

<template>
  <section :class="spacingClasses[spacing]">
    <AppContainer>
      <header
        v-if="title || subtitle"
        :class="['max-w-2xl mb-12', alignClasses[align]]"
      >
        <h2 v-if="title" class="text-3xl md:text-4xl font-display font-bold text-gray-900">
          {{ title }}
        </h2>
        <p v-if="subtitle" class="mt-4 text-lg text-gray-600">
          {{ subtitle }}
        </p>
      </header>

      <slot />
    </AppContainer>
  </section>
</template>
```

**【录屏提示】** 边写边讲。

几个关键点。

**第一，`spacing` 控制区块的垂直间距。** `py-12`、`py-20`、`py-32` 三档。这样全站区块间距统一。

**第二，`align` 控制标题对齐。** `center` 时 `mx-auto` 让标题区居中。

**第三，`header` 只在有标题时渲染。** `v-if` 判断，没标题就不占空间。

**第四，`<slot />` 是内容入口。** 页面把具体内容放进来。

**第五，`as const` 让映射表的类型更精确。**

## 五、具名插槽：多区域内容（约 2 分钟）

好，有时候一个区块需要**多个内容区**。比如一个"左右分栏"的区块，左边图文，右边插图。

这时候用**具名插槽**。

**【录屏提示】** 写一个 `SplitSection`。

```vue
<!-- components/layout/SplitSection.vue -->
<template>
  <section class="py-20">
    <AppContainer>
      <div class="grid grid-cols-1 lg:grid-cols-2 gap-12 items-center">
        <div>
          <slot name="content" />
        </div>
        <div>
          <slot name="media" />
        </div>
      </div>
    </AppContainer>
  </section>
</template>
```

用的时候：

```vue
<SplitSection>
  <template #content>
    <h2>标题</h2>
    <p>描述...</p>
  </template>
  <template #media>
    <NuxtImg src="/hero.png" />
  </template>
</SplitSection>
```

**【录屏提示】** 镜头切回讲师。

**具名插槽让组件支持"多区域"。** 你可以在组件里定义"内容区""媒体区""操作区"等等，页面按需填充。

## 六、作用域插槽：数据回传（约 1 分 30 秒）

还有一种更高级的插槽——**作用域插槽**。

**【录屏提示】** 写一个例子。

```vue
<!-- components/layout/DataList.vue -->
<template>
  <ul>
    <li v-for="(item, index) in items" :key="index">
      <slot :item="item" :index="index" />
    </li>
  </ul>
</template>
```

用的时候：

```vue
<DataList :items="products">
  <template #default="{ item }">
    <ProductCard :product="item" />
  </template>
</DataList>
```

**【录屏提示】** 镜头拉近。

**作用域插槽让父组件能拿到子组件的数据。** 这样组件既控制了"循环结构"，又让父组件决定"每一项怎么渲染"。

**什么时候用？** 当组件有"遍历"或"状态"需要暴露给外部时。比如列表、Tabs、下拉菜单。

## 七、API 设计的度（约 1 分钟）

最后，我讲一个**平衡问题**。

**【录屏提示】** 镜头切回讲师，语气诚恳。

插槽很强大，但**不要为了灵活而灵活**。

如果你的组件有 8 个插槽、12 个 props，那它可能太复杂了。**该拆就拆。**

我的原则是：**优先用 props 表达"确定的配置"，用插槽表达"不确定的内容"。**

- "标题"是确定的 → props
- "内容长什么样"是不确定的 → 插槽

**这个判断标准，你记住就行。**
