## 二、Nuxt + Tailwind 集成坑（约 2 分 30 秒）

**【录屏提示】** 屏幕显示坑清单。

**坑一，样式不生效。**

**现象**：写了 Tailwind 类，但页面没样式。

**原因**：`nuxt.config.ts` 里没配 `css` 字段，或者路径写错。

**解决**：

```ts
export default defineNuxtConfig({
  css: ['~/assets/css/main.css'],
})
```

**坑二，`@import "tailwindcss"` 报错。**

**现象**：CSS 编译失败。

**原因**：`@import` 前面有别的规则，或者没装 `@tailwindcss/vite` 插件。

**解决**：确保 `@import "tailwindcss"` 在文件**最顶部**，且 `vite.plugins` 里配了 `tailwindcss()`。

**坑三，V3 的配置文件残留。**

**现象**：样式行为诡异，或者部分类不生成。

**原因**：项目里还有 `tailwind.config.js` 和 `postcss.config.js`。

**解决**：V4 不需要这两个文件，**删掉**。

**【录屏提示】** 镜头切回讲师。

**坑四，修改配置后不生效。**

**原因**：Nuxt 的配置缓存。

**解决**：**重启 dev server。** 改 `nuxt.config.ts` 后，养成重启的习惯。

## 三、Tailwind 类名坑（约 3 分钟）

**【录屏提示】** 屏幕显示坑清单。

**坑五，动态类名不生成（最经典的坑）。**

**现象**：本地开发正常，上线后样式丢失。

**原因**：用模板字符串拼接类名，Tailwind 扫不到。

**解决**：用**完整的类名映射表**。

```ts
const map = { red: 'text-red-500', blue: 'text-blue-500' }
```

**坑六，默认边框颜色变了。**

**现象**：V3 项目迁移到 V4，边框颜色不对。

**原因**：V4 的 `border` 默认色是 `currentColor`，V3 是 `gray-200`。

**解决**：显式指定边框颜色，或者全局设置默认值。

**坑七，类名顺序不影响优先级。**

**现象**：以为后写的类会覆盖先写的。

**原因**：Tailwind 按**生成顺序**决定优先级，不按书写顺序。

**解决**：用 `tailwind-merge`，或者避免冲突。

**坑八，`@apply` 滥用。**

**现象**：项目变成"用 Tailwind 语法写传统 CSS"。

**原因**：一看到重复就 `@apply`。

**解决**：**优先抽组件**，`@apply` 只用于覆盖第三方样式。

**【录屏提示】** 镜头拉近。

**这八个坑，我建议你截图保存。** 遇到问题时对照检查，能省很多时间。

## 四、SSR 相关坑（约 2 分 30 秒）

**【录屏提示】** 屏幕显示坑清单。

**坑九，访问 `window` 报错。**

**现象**：`window is not defined`。

**原因**：SSR 环境下没有 `window`，但代码在服务端执行了。

**解决**：放在 `onMounted` 里，或用 `import.meta.client` 判断。

```ts
onMounted(() => {
  window.addEventListener('scroll', onScroll)
})
```

**坑十，暗色模式闪烁。**

**现象**：页面先白后黑。

**原因**：`dark` 类设置太晚。

**解决**：**内联脚本**在渲染前设置（我们 7.2 讲过）。

**坑十一，Teleport 水合不一致。**

**现象**：控制台报 hydration mismatch。

**原因**：`<Teleport>` 在 SSR 时目标不存在。

**解决**：用 `<ClientOnly>` 包裹。

**坑十二，`Date` 对象序列化问题。**

**现象**：服务端和客户端数据不一致。

**原因**：`Date` 序列化后变字符串。

**解决**：服务端就用 ISO 字符串，客户端需要时再 `new Date()`。

**【录屏提示】** 镜头切回讲师。

**SSR 的坑，本质都是"服务端没有浏览器 API"。** 记住这一点，大部分坑都能预判。

## 五、性能与部署坑（约 1 分 30 秒）

**【录屏提示】** 屏幕显示坑清单。

**坑十三，首屏图懒加载。**

**现象**：LCP 很慢。

**原因**：给首屏大图加了 `loading="lazy"`。

**解决**：**首屏图不加懒加载**，用 `preload` + `fetchpriority="high"`。

**坑十四，图片没设尺寸。**

**现象**：CLS 分数差。

**原因**：图片加载后撑开布局。

**解决**：`width` 和 `height` **必填**。

**坑十五，环境变量泄漏。**

**现象**：API 密钥出现在客户端代码里。

**原因**：用了 `NUXT_PUBLIC_` 前缀。

**解决**：**密钥不加 `NUXT_PUBLIC_` 前缀。**

**坑十六，缓存策略和部署环境不匹配。**

**现象**：配了 `isr` 但不生效。

**原因**：部署到了纯静态托管。

**解决**：**先确定部署目标，再配缓存策略。**

## 六、排错方法论（约 1 分钟）

**【录屏提示】** 镜头切回讲师，语气放慢。

最后，我讲**排错的方法论**。

**第一，看控制台。** 90% 的问题，控制台有提示。

**第二，看网络面板。** 请求失败、返回错误，这里能看到。

**第三，看构建产物。** 样式丢失，去 `dist` 里搜类名。

**第四，二分法。** 注释掉一半代码，看问题是否还在。

**第五，最小复现。** 把问题剥离到一个最小示例，往往就找到原因了。

**【录屏提示】** 镜头拉近。

**别猜，用工具看。** 这是排错的基本原则。

**还有，善用搜索。** 报错信息直接搜，大概率有人遇到过。
