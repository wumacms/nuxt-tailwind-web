# 9.1-从零到一：完整页面复刻

**【录屏提示】** 开场：讲师出镜，背景为一张全新的设计稿（Figma）。

这一节我**不剪辑**。遇到问题就查、就试、就调整。**我要让你看到真实的开发是什么样的。**

**【录屏提示】** 镜头拉近，语气诚恳。

因为真实的开发不是"一次写对"，而是"边写边调"。**你看到我卡住、试错、改方案，这才是最有价值的部分。**

## 二、拿到设计稿先做什么（约 2 分钟）

**【录屏提示】** 切到 Figma，展示一张全新的设计稿。

这是我们这一节要实现的设计稿——一个**"服务介绍页"**。

拿到设计稿，我**不急着写代码**。我先做三件事。

**第一，看整体结构。** 从上到下，我数一下有几个区块：

- 顶部：页面标题 + 面包屑
- 第一屏：左侧文案 + 右侧插图
- 第二屏：服务列表（3 个卡片）
- 第三屏：流程步骤（4 步）
- 第四屏：CTA

**第二，看能复用什么。** 我脑子里快速过一遍：

- 页面标题 → `PageHero`（已有的）
- 面包屑 → `AppBreadcrumb`（已有的）
- 图文混排 → 和 About 页很像，可以复用 `AboutIntro` 的模式
- 卡片列表 → `AppMediaCard`（已有的）
- 流程步骤 → **新的，要写**
- CTA → `CTASection`（已有的）

**第三，看需要哪些新东西。** 我发现只有一个：**流程步骤组件**。其他都能复用。

**【录屏提示】** 镜头切回讲师。

**这个过程叫"拆解"。** 好的开发者，拿到需求第一件事不是写代码，是**拆解成"已有的"和"要写的"**。

**你会发现，大部分工作其实是"复用 + 组装"。** 只有一小部分是真正的新东西。

    <ServiceProcess />

**【录屏提示】** 边写边讲。

**我先写"骨架"——把页面结构搭出来。**

每个区块一个组件，先不实现，只留占位。**这样我能立刻看到页面的整体框架。**

**【录屏提示】** 切浏览器，展示空白骨架。

你看，现在页面是空的，但结构对了。**下一步，逐个填充。**

**【录屏提示】** 镜头拉近。

**这个"先结构、后填充"的顺序很重要。** 如果你一个区块一个区块地写，写到后面容易忘记整体。**先把骨架搭好，再填肉。**

## 五、写新组件（约 2 分钟）

**【录屏提示】** 新建 `components/sections/ServiceProcess.vue`。

```vue
<script setup lang="ts">
interface Step {
  number: string
  title: string
  description: string
}

defineProps<{ steps: Step[] }>()
</script>

<template>
  <PageSection title="服务流程" subtitle="四步完成数字化转型">
    <div class="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-4 gap-8">
      <div v-for="(step, index) in steps" :key="step.number" class="relative">
        <!-- 连接线（桌面端） -->
        <div
          v-if="index < steps.length - 1"
          class="hidden lg:block absolute top-6 left-full w-full h-px bg-gray-200 -translate-y-1/2"
          style="width: calc(100% - 3rem)"
        />

        <div class="relative">
          <div class="w-12 h-12 rounded-full bg-brand-500 text-white flex items-center justify-center font-display font-bold text-lg">
            {{ step.number }}
          </div>
          <h3 class="mt-4 text-lg font-semibold">{{ step.title }}</h3>
          <p class="mt-2 text-sm text-gray-600 leading-relaxed">{{ step.description }}</p>
        </div>
      </div>
    </div>
  </PageSection>
</template>
```

**【录屏提示】** 边写边讲。

**第一，`grid-cols-4` 在桌面端。** 手机 1 列、平板 2 列、桌面 4 列。

**第二，连接线。** 用绝对定位，`left-full` 定位到下一个元素的起点。`calc(100% - 3rem)` 让它避开圆点。

**第三，只在桌面端显示连接线。** 因为手机上换行了，连线没意义。

**【录屏提示】** 切浏览器，展示效果。

好，看起来不错。**但如果设计稿要求连接线在圆点中间呢？** 我调一下 `top` 值。**这就是真实的开发——边看边调。**

## 六、复盘这个流程（约 1 分钟）

**【录屏提示】** 镜头切回讲师。

我们回顾一下刚才的过程：

**第一，拆解。** 看结构、看复用、看新东西。

**第二，搭骨架。** 先写页面结构，不管实现。

**第三，填内容。** 优先复用，其次组合，最后新写。

**第四，微调。** 对着设计稿调细节。

**【录屏提示】** 镜头拉近，语气放慢。

**这个流程，适用于任何页面。** 你把它内化成习惯，开发效率会大幅提升。

**核心思想是：先想清楚"要做什么"，再动手"怎么做"。** 不要一上来就写代码。
