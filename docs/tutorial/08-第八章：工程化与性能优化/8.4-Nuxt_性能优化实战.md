## 二、Core Web Vitals 是什么（约 1 分 30 秒）

**【录屏提示】** 屏幕显示三个指标的图示。

**LCP（Largest Contentful Paint）**：最大内容绘制。**首屏最大元素出现的时间。** 目标 < 2.5s。

**CLS（Cumulative Layout Shift）**：累计布局偏移。**页面跳动程度。** 目标 < 0.1。

**INP（Interaction to Next Paint）**：交互到下次绘制。**用户点击后多久有响应。** 目标 < 200ms。

**【录屏提示】** 镜头切回讲师。

**这三个指标直接影响 SEO 排名和用户留存。** 企业站必须关注。

---

## 三、优化 LCP（约 3 分钟）

**【录屏提示】** 屏幕显示 LCP 优化清单。

**LCP 通常是首屏大图或大标题。** 优化手段：

**第一，首屏图预加载。**

```vue
<NuxtImg src="/hero.jpg" preload fetchpriority="high" />
```

**第二，不要在首屏用懒加载。** `loading="lazy"` 会延迟 LCP。

**第三，用 `NuxtImg` 优化格式。** WebP、AVIF 体积小，加载快。

**第四，关键 CSS 内联。** Nuxt 会自动做部分内联。

**第五，减少服务端渲染时间。**

- 用 `routeRules` 做 SSG 或 ISR
- 数据获取用缓存
- 避免在 SSR 里做重计算

**第六，用 CDN。** 静态资源走 CDN，减少延迟。

**【录屏提示】** 镜头拉近。

**LCP 优化的核心是"让首屏最大元素尽快出现"。** 优先级是：**减少等待（缓存/CDN）> 减小体积（图片优化）> 提高优先级（preload）。**

---

## 四、优化 CLS（约 2 分钟）

**【录屏提示】** 镜头切回讲师。

**CLS 是"页面跳动"。** 常见原因和解决：

**第一，图片没设尺寸。**

```vue
<NuxtImg src="..." width="800" height="600" />
```

**有了尺寸，浏览器提前预留空间。**

**第二，字体加载导致跳。**

```css
@font-face {
  font-family: 'Inter';
  font-display: swap;  /* 或用 optional */
}
```

**`swap` 会先显示后备字体，加载后切换，可能有轻微跳动。** `optional` 更激进，如果字体没及时加载就不用了。

**第三，动态插入内容。**

比如广告、Cookie 提示条。**要给它们预留空间，或者用绝对定位。**

**第四，异步加载的组件。**

用 `<Suspense>` 的 fallback 占位。

**【录屏提示】** 镜头切回讲师。

**CLS 的核心是"提前预留空间"。** 任何"加载后才出现"的元素，都要考虑它会不会把下面的内容"顶下去"。

---

## 五、优化 INP（约 1 分 30 秒）

**【录屏提示】** 镜头切回讲师，语气放慢。

**INP 是"交互响应速度"。** 优化手段：

**第一，减少长任务。** 一个任务超过 50ms 就叫"长任务"，会阻塞主线程。

**第二，拆分大组件。** 用 `defineAsyncComponent` 懒加载非关键组件。

**第三，用 `requestIdleCallback` 或 `setTimeout` 拆任务。**

**第四，避免在渲染里做重计算。** 用 `computed` 缓存。

**第五，事件监听用 `passive`。** 我们 3.4 讲过。

**【录屏提示】** 镜头拉近。

**INP 的排查用 Chrome DevTools 的 Performance 面板。** 录制一段交互，看哪个任务耗时最长。

## 六、Nuxt 特有的优化（约 2 分钟）

**【录屏提示】** 屏幕显示 Nuxt 优化清单。

**第一，`<LazyXxx>` 组件。**

```vue
<LazyHeavyChart v-if="showChart" />
```

**加 `Lazy` 前缀，组件会延迟加载。**

**第二，`defineAsyncComponent`。**

```ts
const HeavyComponent = defineAsyncComponent(() => import('./Heavy.vue'))
```

**第三，路由级别的懒加载。** Nuxt 默认就做了，每个页面单独打包。

**第四，Payload 优化。**

```ts
useFetch('/api/data', { 
  pick: ['id', 'name'],  // 只传需要的字段到客户端
})
```

**`pick` 能减少 SSR 到客户端的数据量。**

**第五，`<ClientOnly>` 包裹非关键客户端组件。**

**【录屏提示】** 镜头切回讲师。

**这些优化的共同思路是：** **"不是首屏必需的，就往后推。"**

**第一，Lighthouse。** 本地跑，看分数。

**第二，Web Vitals 库。** 在真实用户环境收集数据。

```ts

```

**第三，Google Search Console。** 会报告真实用户的 Core Web Vitals 数据。

**【录屏提示】** 镜头拉近。

**本地 Lighthouse 分数高，不代表真实用户体感好。** 一定要看真实数据。
