## 二、回顾渲染模式（约 1 分 30 秒）

**【录屏提示】** 屏幕显示四种模式的对比。

快速回顾一下：

**SSR**：每次请求服务端渲染。**内容实时，但服务器有压力。**

**SSG**：构建时预渲染。**最快，但内容更新要重新构建。**

**ISR**：增量静态再生。**定期后台更新，兼顾速度和新度。**

**SWR**：陈旧内容优先。**先返回缓存，后台更新。**

**【录屏提示】** 镜头切回讲师。

**加上 SPA（客户端渲染），一共五种。** 我们在 `routeRules` 里按路径配置。

## 三、`routeRules` 配置（约 3 分钟）

**【录屏提示】** 打开 `nuxt.config.ts`，写配置。

```ts
export default defineNuxtConfig({
  routeRules: {
    // 首页：预渲染
    '/': { prerender: true },

    // 关于、联系：预渲染
    '/about': { prerender: true },
    '/contact': { prerender: true },

    // 产品列表：SWR，缓存 1 小时
    '/products': { swr: 3600 },

    // 产品详情：ISR，缓存 1 小时
    '/products/**': { isr: 3600 },

    // 新闻列表：SWR，缓存 10 分钟
    '/news': { swr: 600 },

    // 新闻详情：ISR，缓存 1 天
    '/news/**': { isr: 86400 },

    // 后台：纯客户端
    '/admin/**': { ssr: false },

    // API：缓存 5 分钟
    '/api/products': { cache: { maxAge: 300 } },
  },
})
```

**【录屏提示】** 边写边讲。

几个关键点。

**第一，`prerender: true` 是 SSG。** 构建时生成静态 HTML。

**第二，`swr: 秒数`。** Stale-While-Revalidate。**用户先拿到缓存，后台异步更新。**

**第三，`isr: 秒数`。** Incremental Static Regeneration。**过期后的第一个请求触发重新生成。**

**第四，`ssr: false`。** 这个路径走 SPA。

**第五，`cache`。** 给 API 响应加缓存。

**【录屏提示】** 镜头拉近，语气加重。

**SWR 和 ISR 的区别，很多人搞不清。**

- **SWR**：过期后，**所有用户**都拿旧内容，后台更新。更新完成后，新用户拿新内容。
- **ISR**：过期后，**第一个用户**触发重新生成，等生成完才返回新内容。

**简单说：SWR 更"旧但快"，ISR 更"新但慢一次"。**

## 四、缓存策略的设计（约 2 分钟）

**【录屏提示】** 镜头切回讲师。

**怎么决定每个页面用什么缓存？**

我给出一个判断框架：

**第一，内容变化频率。**

- 几乎不变（关于、联系）→ SSG
- 每天变（产品、新闻）→ ISR/SWR 长缓存
- 实时变（库存、价格）→ SSR 或短缓存

**第二，SEO 重要性。**

- 重要 → 一定要 SSR/SSG/ISR，别用 SPA
- 不重要（后台）→ SPA 也行

**第三，个性化程度。**

- 千人千面 → 不能缓存，用 SSR
- 所有人一样 → 可以缓存

**【录屏提示】** 镜头拉近。

**企业站大部分页面是"所有人一样"，所以能大量用缓存。** 这是它比后台系统"好优化"的地方。

## 五、部署环境影响（约 2 分钟）

**【录屏提示】** 镜头切回讲师，语气放慢。

**缓存策略和部署环境强相关。**

**如果你部署到纯静态托管（比如 Netlify、Vercel 的静态模式）：**

- `prerender` 可以
- `swr` 和 `isr` **不支持**，因为没有服务端
- `ssr: false` 可以

**如果你部署到 Node 服务：**

- 所有模式都支持
- 但需要自己管理缓存存储

**如果你部署到支持边缘渲染的平台（Vercel、Netlify Functions）：**

- `isr`、`swr` 由平台托管
- 最省心

**【录屏提示】** 镜头切回讲师。

**所以选渲染策略之前，先确定部署目标。** 不然配了 `isr` 但部署到静态托管，会失败。

## 六、CDN 缓存（约 1 分 30 秒）

**【录屏提示】** 屏幕显示 CDN 缓存层级。

**CDN 是"第一层缓存"。** 静态资源（JS、CSS、图片）都应该走 CDN。

**配置要点：**

**第一，带 hash 的文件（`app.a1b2c3.js`）设长缓存。** 一年都行，因为内容变了文件名就变。

**第二，HTML 不缓存或短缓存。** 因为 HTML 可能频繁更新。

**第三，用 `Cache-Control` 头控制。**

```text
Cache-Control: public, max-age=31536000, immutable
```

**【录屏提示】** 镜头切回讲师。

**Nuxt 的 Nitro 会自动给静态资源加合适的缓存头。** 你一般不用手动配。

**但如果你用了第三方 CDN，要确认它尊重这些头。**
