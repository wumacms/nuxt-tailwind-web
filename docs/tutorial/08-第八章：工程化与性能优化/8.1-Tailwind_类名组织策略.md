# 8.1-Tailwind_类名组织策略

**【录屏提示】** 开场：讲师出镜，背景为一段超长的 class 字符串。

---

## 一、开场白（约 30 秒）

好，欢迎来到第八章。

前面七章，我们把功能、SEO、设计系统都做完了。从这一章开始，我们讲**上线前的最后一公里**——工程化与性能优化。

这一节讲**类名组织策略**。

Tailwind 被吐槽最多的就是"类名太长、太乱"。一个 div 上挂十几个类，看起来很吓人。这一节，我们讲清楚**怎么让类名可读、可维护**。

---

## 二、类名"乱"的真相（约 1 分 30 秒）

**【录屏提示】** 屏幕显示一段长类名。

先看一个典型例子：

```html
<div class="flex items-center justify-between p-4 bg-white rounded-md shadow-sm border border-gray-100 hover:shadow-md transition-shadow">
```

18 个类，确实不短。

**【录屏提示】** 镜头切回讲师。

但我要说：**这不叫"乱"，这叫"密集"。**

**"乱"是随机的、无序的。** 而这段类名是**有结构的**：布局、间距、背景、圆角、阴影、边框、交互。

**你按顺序读，就能"读"出这个元素的完整样式。** 这正是 Tailwind 的价值——**样式就地可见，不用跳到 CSS 文件。**

**问题是：怎么保持这个"结构"？** 这就是这一节要讲的。

---

## 三、类名排序（约 2 分 30 秒）

**【录屏提示】** 屏幕显示推荐排序。

我推荐一个**固定的排序顺序**：

**第一，布局。** `flex`、`grid`、`block`、`relative`、`absolute`。

**第二，盒模型。** `w-*`、`h-*`、`p-*`、`m-*`。

**第三，排版。** `text-*`、`font-*`、`leading-*`。

**第四，视觉。** `bg-*`、`border-*`、`rounded-*`、`shadow-*`。

**第五，交互。** `hover:`、`focus:`、`transition-*`。

**第六，响应式。** `md:`、`lg:`。

**【录屏提示】** 边讲边对照示例。

```html
<div class="
  flex items-center justify-between
  p-4
  text-sm
  bg-white border border-gray-100 rounded-md shadow-sm
  hover:shadow-md transition-shadow
">
```

**这样分组后，可读性大幅提升。**

**【录屏提示】** 镜头切回讲师。

**但靠人手动排，很难坚持。** 所以要用工具。

---

## 四、Prettier 插件（约 2 分 30 秒）

**【录屏提示】** 终端安装。

```bash
npm install -D prettier prettier-plugin-tailwindcss
```

然后新建 `.prettierrc`：

```json
{
  "plugins": ["prettier-plugin-tailwindcss"],
  "semi": false,
  "singleQuote": true
}
```

**【录屏提示】** 边写边讲。

**`prettier-plugin-tailwindcss` 会自动按 Tailwind 推荐顺序排序类名。**

**【录屏提示】** 演示格式化。

你看，我保存文件时，类名自动排好了。**不需要手动整理。**

**这个插件是 Tailwind 项目的必备。** 它做了几件事：

**第一，按官方推荐顺序排序类名。**

**第二，识别 `:class` 绑定里的字符串。**

**第三，移除重复的类。**

**【录屏提示】** 镜头拉近。

**注意，配置里 `plugins` 数组的位置很重要。** 某些版本的 Prettier 要求这个插件放最后。**如果排序不生效，先检查配置。**

## 五、长类名的处理（约 1 分 30 秒）

**【录屏提示】** 镜头切回讲师。

**即使排好序，有些类名还是太长。** 怎么处理？

**方案一，换行。** Prettier 会自动换行，但可能不够整齐。可以用 `printWidth` 控制。

**方案二，抽组件。** 这是我们 2.4 讲的——**有结构的重复，抽组件。**

**方案三，用 `@apply`。** 但我们说过，慎用。

**方案四，CVA（Class Variance Authority）。**

```ts
import { cva } from 'class-variance-authority'

const button = cva('inline-flex items-center rounded-md font-medium', {
  variants: {
    variant: {
      primary: 'bg-brand-500 text-white',
      secondary: 'bg-gray-100 text-gray-900',
    },
    size: {
      sm: 'px-3 py-1.5 text-sm',
      md: 'px-4 py-2 text-base',
    },
  },
})
```

**【录屏提示】** 镜头切回讲师。

**CVA 是我们 4.1 讲的"类名映射表"的升级版。** 它把变体、默认值、组合逻辑封装得更优雅。

**如果你的项目有大量多变体组件，CVA 值得引入。** 简单项目用我们 4.1 的手写映射表就够了。

## 六、ESLint 规则（约 1 分 30 秒）

**【录屏提示】** 镜头切回讲师，语气放慢。

**除了排序，还要防止"坏习惯"。**

我推荐几类 ESLint 规则。

**第一，防止动态拼接类名。**

```ts
// 错误
const cls = `text-${color}-500`
```

可以用自定义规则或 review 检查。

**第二，防止 `@apply` 滥用。** 可以设置一个上限，比如一个文件最多几个 `@apply`。

**第三，防止裸写颜色值。**

```html
<!-- 应该用令牌 -->
<div style="color: #2563eb">
```

**这些规则不是必须，但能让团队保持一致性。**
