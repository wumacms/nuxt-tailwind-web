# 8.3-构建体积优化

**【录屏提示】** 开场：讲师出镜，背景为构建产物分析图。

---

## 一、开场白（约 30 秒）

好，欢迎回来。

这一节我们讲**构建体积优化**。

Tailwind 的卖点之一是"按需生成"——只打包你用到的类。但**"按需"有个前提：类名必须是"可静态分析"的**。

这一节，我们讲清楚**为什么体积会变大，以及怎么排查和优化**。

---

## 二、V4 的按需生成机制（约 2 分钟）

**【录屏提示】** 屏幕显示扫描和生成的流程图。

V4 的机制是：

**第一，扫描源码。** 它会自动扫描项目里的文件，找到所有"看起来像类名"的字符串。

**第二，生成 CSS。** 只生成找到的类。

**第三，输出产物。** 通常只有几 KB 到几十 KB。

**【录屏提示】** 镜头切回讲师。

**对比 V3：** V3 用 `content` 配置指定扫描范围，V4 是自动检测。

**自动检测方便，但有个问题：它会扫描"所有文件"**，包括你可能不想扫的。**而且它无法识别动态拼接的类名。**

---

## 三、动态类名问题（约 2 分 30 秒）

**【录屏提示】** 屏幕显示拼接代码和结果。

**这是老问题，我们再强调一次。**

```ts
const cls = `text-${color}-500`
```

**Tailwind 扫描源码时看到的字符串是 `text-${color}-500`**，它不知道 `color` 是什么，所以**不会生成任何类**。

**【录屏提示】** 演示：构建后搜索 `text-red-500`，找不到。

**结果：生产环境样式丢失。**

**解决方案：**

**第一，用完整类名映射表。**

```ts
const colorMap = {
  red: 'text-red-500',
  blue: 'text-blue-500',
}
```

**第二，用 `@source inline()` 强制生成。**

```css
@source inline("text-red-500 text-blue-500 text-green-500");
```

**【录屏提示】** 镜头切回讲师。

**优先用方案一。** 方案二是"补丁"，容易漏。

---

## 四、扫描范围的优化（约 2 分钟）

**【录屏提示】** 镜头切回讲师，语气放慢。

**V4 自动扫描有个问题：它会扫到不该扫的文件。**

比如：

- `node_modules/` 里的第三方包（通常自动排除）
- `dist/` 构建产物
- 测试文件
- 文档里的示例代码

**【录屏提示】** 打开 `main.css`，写 `@source`。

```css
@import "tailwindcss";

/* 只扫描这些目录 */
@source "../components";
@source "../pages";
@source "../layouts";

/* 明确排除 */
@source not "../docs";
@source not "../node_modules";
```

**【录屏提示】** 边写边讲。

**`@source` 指定扫描范围，`@source not` 排除。**

**好处是：** 减少扫描时间，避免误扫到"看起来像类名"的字符串（比如文档里的示例），导致生成无用 CSS。

**【录屏提示】** 镜头拉近。

**注意：V4 默认已经排除了 `.gitignore` 里的内容。** 所以 `node_modules`、`dist` 一般不用手动排除。

**但如果你有特殊目录（比如 `docs/`），建议显式排除。**

## 五、分析构建产物（约 2 分钟）

**【录屏提示】** 终端安装分析工具。

```bash
npm install -D rollup-plugin-visualizer
```

然后配到 Vite：

```ts
import { visualizer } from 'rollup-plugin-visualizer'

export default defineNuxtConfig({
  vite: {
    plugins: [
      visualizer({ filename: 'stats.html', gzipSize: true }),
    ],
  },
})
```

**【录屏提示】** 构建后打开 `stats.html`。

```bash
npm run build
open stats.html
```

**你会看到一张"树状图"，显示每个模块的体积。**

**【录屏提示】** 镜头切回讲师。

**重点看几块：**

**第一，CSS 体积。** 正常情况下 Tailwind 产物应该 < 50KB（gzip 后 < 10KB）。

**第二，JS 体积。** 看有没有意外引入的大依赖。

**第三，第三方库。** 比如 `moment`、`lodash` 这类"体积大户"。

---

## 六、常见的体积陷阱（约 1 分 30 秒）

**【录屏提示】** 屏幕显示陷阱清单。

**第一，引入整个 UI 库。** 比如 `import ElementPlus from 'element-plus'`，会打包全部组件。**要用按需引入。**

**第二，`lodash` 全量引入。** 应该用 `lodash-es` 或按需引入单个函数。

**第三，`moment` 时区数据。** 换成 `dayjs` 或 `date-fns`，小很多。

**第四，图片没优化。** 我们 6.6 讲过了。

**第五，重复依赖。** 用 `npm ls <package>` 检查有没有多版本共存。

**【录屏提示】** 镜头切回讲师。

**排查原则是：先看"大头"，再优化"小头"。** 一个 500KB 的依赖，比优化 10 个 1KB 的类名更值。
