# 8.2-样式冲突与优先级

**【录屏提示】** 开场：讲师出镜，背景为 DevTools 里被划掉的样式。

---

## 一、开场白（约 30 秒）

好，欢迎回来。

这一节我们讲**样式冲突与优先级**。

只要你写 CSS，就一定会遇到"我写的样式没生效"。Tailwind 项目里，这个问题的表现形式和传统 CSS 略有不同。这一节，我们讲清楚**冲突的原因和解决思路**。

---

## 二、CSS 层叠回顾（约 2 分钟）

**【录屏提示】** 屏幕显示层叠优先级。

先快速回顾 CSS 的层叠规则。**优先级从高到低：**

**第一，`!important`。**

**第二，内联样式（`style=""`）。**

**第三，选择器特异性。** ID > 类 > 标签。

**第四，源码顺序。** 同特异性下，后写的赢。

**【录屏提示】** 镜头切回讲师。

**Tailwind 的原子类都是"单类选择器"，特异性都是 `0,1,0`。**

**所以两个 Tailwind 类冲突时，胜负由"源码顺序"决定——而源码顺序由 Tailwind 的生成顺序决定。**

**这就是很多"奇怪"冲突的根源。**

---

## 三、常见冲突场景（约 3 分钟）

**【录屏提示】** 屏幕逐个显示冲突场景。

**场景一，`p-4` 和 `px-6` 冲突。**

```html
<div class="p-4 px-6">
```

`p-4` 设置了四个方向的内边距，`px-6` 覆盖了左右。**结果：上下 16px，左右 24px。**

**这个不是冲突，是"部分覆盖"。** Tailwind 生成顺序保证 `px-*` 在 `p-*` 之后，所以覆盖成功。

**【录屏提示】** 镜头切回讲师。

**但如果你写反了顺序呢？**

```html
<div class="px-6 p-4">
```

**结果还是一样。** 因为 Tailwind 按"生成顺序"决定，不按"你写的顺序"。

**这是 Tailwind 的一个"反直觉"点：类名的书写顺序不影响优先级。**

**场景二，`text-red-500` 和 `text-blue-500` 冲突。**

```html
<div class="text-red-500 text-blue-500">
```

**哪个生效？** 由 Tailwind 生成顺序决定，不按书写顺序。**结果不确定，应该避免。**

**场景三，组件样式和外部样式冲突。**

```vue
<!-- AppButton.vue -->
<button class="bg-brand-500 ...">

<!-- 使用处 -->
<AppButton class="bg-red-500" />
```

**【录屏提示】** 镜头拉近，语气加重。

**这里的 `bg-red-500` 会不会覆盖组件内部的 `bg-brand-500`？**

**取决于 Vue 的 `class` 合并机制。** Vue 会把外部 class 和组件根元素的 class 合并，**但顺序是"组件内部在前，外部在后"**。

**所以 `bg-red-500` 在源码里排在后面，可能覆盖成功，也可能不成功——取决于 Tailwind 生成顺序。**

**这是 Tailwind 项目里最常见的"覆盖不生效"问题。**

---

## 四、解决方案（约 2 分 30 秒）

**【录屏提示】** 屏幕显示四个方案。

**方案一，用 `tailwind-merge`。**

这是最推荐的方案。

```bash
npm install tailwind-merge
```

```ts
import { twMerge } from 'tailwind-merge'

const classes = twMerge('bg-brand-500 px-4', 'bg-red-500')
// 结果：'px-4 bg-red-500'
```

**它会智能合并冲突的类，保留后写的。** 这是 UI 库的标准做法。

**方案二，用 CSS 变量。**

组件的关键样式用 CSS 变量暴露。

```vue
<button :style="{ '--btn-bg': bg }" class="bg-(--btn-bg)">
```

**【录屏提示】** 镜头切回讲师。

**方案三，用 `!important`。**

```html
<AppButton class="!bg-red-500" />
```

**Tailwind 的 `!` 前缀能加 `!important`。**

**但我强烈建议：尽量别用。** 它是"最后的手段"，一旦用了，下次要覆盖它就更难。

**方案四，重构组件。**

如果某个样式经常被外部覆盖，说明**组件的 API 设计有问题**。应该把它做成 prop。

```vue
<AppButton variant="danger">删除</AppButton>
```

**而不是：**

```vue
<AppButton class="!bg-red-500">删除</AppButton>
```

**【录屏提示】** 镜头切回讲师。

**方案四是"治本"的。** 前三个是"治标"。**遇到冲突，先想"是不是组件设计不对"。**

## 五、`@layer` 与优先级（约 1 分 30 秒）

**【录屏提示】** 镜头切回讲师，语气放慢。

**Tailwind 有层（layer）的概念。** V4 里主要是 `base`、`components`、`utilities`。

**层之间有优先级：`utilities` > `components` > `base`。**

**所以你写在 `@layer base` 里的样式，优先级低于任何工具类。** 这是设计好的。

**如果你想自定义的类和 Tailwind 工具类同优先级，写在 `@utility` 里。**

**【录屏提示】** 镜头拉近。

**理解层，能帮你判断"为什么这个样式不生效"。**

**大部分"不生效"，是因为它写在了低优先级的层里。**

## 六、调试方法（约 1 分钟）

**【录屏提示】** 屏幕显示 DevTools 截图。

**遇到冲突，怎么调试？**

**第一，DevTools 看元素。** 看哪些样式被划掉了，被谁覆盖了。

**第二，看"Computed"标签。** 看最终生效的值。

**第三，看源码顺序。** 在"Styles"面板里，从上到下就是优先级从高到低。

**第四，二分法。** 逐个删类名，看哪个类生效了。

**【录屏提示】** 镜头切回讲师。

**别猜，用工具看。** 这是排错的基本原则。
