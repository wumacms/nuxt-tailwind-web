# 7.5-可访问性（a11y）

**【录屏提示】** 开场：讲师出镜，背景为屏幕阅读器和键盘操作演示。

---

## 一、开场白（约 30 秒）

好，欢迎回来。这是第七章的最后一节。

这一节我们讲**可访问性**，英文简称 **a11y**（accessibility，a + 11 个字母 + y）。

很多同学觉得 a11y 是"额外工作"。但我要说——**a11y 不是加分项，是必选项。**

**它不只服务于残障用户。** 键盘用户、临时受伤的人、在强光下看屏幕的人，都会受益。**而且对 SEO 也有好处**，因为搜索引擎也依赖语义化标签。

---

## 二、a11y 的四个维度（约 2 分钟）

**【录屏提示】** 屏幕显示四个维度。

a11y 通常从四个维度看。

**第一，视觉。** 色盲用户、低视力用户。要保证**对比度**和**不只用颜色传达信息**。

**第二，听觉。** 视频要有字幕，音频要有文字稿。

**第三，运动。** 键盘操作、减少动效（我们上一节讲过了）。

**第四，认知。** 文案清晰、结构一致、错误信息明确。

**【录屏提示】** 镜头切回讲师。

**企业站最常做的是第一和第三。** 这一节重点讲这两个。

---

## 三、语义化标签（约 2 分钟）

**【录屏提示】** 屏幕对比"div 汤"和"语义化"结构。

先看一个对比。

**不好的写法：**

```html
<div class="header">
  <div class="nav">
    <div class="nav-item">首页</div>
  </div>
</div>
<div class="main">
  <div class="article">...</div>
</div>
```

**好的写法：**

```html
<header>
  <nav>
    <a href="/">首页</a>
  </nav>
</header>
<main>
  <article>...</article>
</main>
```

**【录屏提示】** 镜头切回讲师。

**区别在哪？**

**语义化标签告诉屏幕阅读器"这是什么"。** 用户可以用快捷键在 `header`、`nav`、`main`、`article` 之间跳转。

**`div` 什么都不告诉它。** 屏幕阅读器只能从头读到尾。

**企业站的正确用法：**

- `<header>` 顶部导航
- `<nav>` 导航区域
- `<main>` 主内容（**一页只能有一个**）
- `<article>` 独立的文章
- `<section>` 有主题的区块
- `<aside>` 侧边栏
- `<footer>` 页脚

**配合 `aria-label` 区分多个同类元素：**

```html
<nav aria-label="主导航">...</nav>
<nav aria-label="页脚导航">...</nav>
```

## 四、焦点管理（约 2 分 30 秒）

**【录屏提示】** 打开代码，演示焦点样式。

**键盘用户靠 `Tab` 键导航。** 焦点在哪个元素上，必须有**清晰的视觉反馈**。

**问题：浏览器默认的焦点环很难看**，很多人用 `focus:outline-none` 去掉它。**这是大错。**

**【录屏提示】** 镜头拉近，语气加重。

**去掉焦点环 = 键盘用户完全迷失。**

**正确做法是用 `focus-visible`。**

```html
<button class="focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-brand-500 focus-visible:ring-offset-2">
```

**`focus-visible` 的特点是：**

- **键盘导航时**，显示焦点环
- **鼠标点击时**，不显示

**【录屏提示】** 镜头切回讲师。

**这样既美观，又保留了键盘用户的可访问性。** 这是现代 Web 的标准做法。

**所有可交互元素都要有焦点样式**：按钮、链接、输入框、自定义控件。

## 五、颜色对比度（约 1 分 30 秒）

**【录屏提示】** 屏幕显示对比度示例。

**WCAG 标准要求：**

- **正文文字**：对比度至少 **4.5:1**
- **大号文字**（18pt+ 或 14pt+ 加粗）：至少 **3:1**
- **UI 组件边界**：至少 **3:1**

**【录屏提示】** 镜头切回讲师。

**怎么检查？**

**第一，浏览器 DevTools。** 选中元素，看颜色旁边的对比度提示。

**第二，在线工具。** WebAIM Contrast Checker。

**第三，Lighthouse。** 会报告对比度问题。

**常见坑：**

- **浅灰文字放在白底上**——看起来"高级"，但对比度不够
- **品牌色按钮上的白字**——品牌色太浅时，白字看不清

**解决方案：用品牌色的深色版本做按钮背景，或者用深色文字。**

## 六、`sr-only` 与 ARIA（约 1 分 30 秒）

**【录屏提示】** 镜头切回讲师，语气放慢。

**有些信息需要"给屏幕阅读器，但不显示"。**

比如一个图标按钮，视觉上是"×"，但屏幕阅读器要读"关闭"。

```html
<button aria-label="关闭">
  <Icon name="x" />
</button>
```

**或者用 `sr-only`：**

```html
<button>
  <Icon name="x" />
  <span class="sr-only">关闭</span>
</button>
```

**【录屏提示】** 镜头拉近。

**`sr-only` 是 Tailwind 提供的类，让内容"视觉隐藏但屏幕阅读器可读"。**

**注意：不要用 `display: none` 或 `visibility: hidden`**，那样屏幕阅读器也读不到。

**ARIA 属性常用：**

- `aria-label`：给元素一个可读的名字
- `aria-hidden="true"`：让屏幕阅读器忽略（用于装饰性元素）
- `aria-expanded`：展开状态（用于折叠菜单）
- `aria-current`：当前项（用于导航）
- `aria-live`：动态区域（用于 Toast）

**ARIA 的第一原则是：不要用 ARIA。** 如果原生 HTML 能表达，就别加 ARIA。**语义化标签优先。**

## 七、a11y 检查清单（约 1 分钟）

**【录屏提示】** 屏幕显示检查清单。

我总结一份企业站的 a11y 检查清单：

**第一，所有图片有 `alt`。** 装饰性图片用 `alt=""`。

**第二，所有可交互元素可键盘操作。** 用 `Tab` 键走一遍。

**第三，所有可交互元素有焦点样式。** 用 `focus-visible:`。

**第四，文字对比度达标。** 正文 4.5:1。

**第五，用语义化标签。** `header`、`nav`、`main`、`article`。

**第六，表单有 label。** 用 `for` 关联。

**第七，图标按钮有 `aria-label`。**

**第八，动态内容用 `aria-live`。**

**第九，用 `motion-safe:` 尊重减少动效。**

**第十，Lighthouse 的 Accessibility 分数 ≥ 95。**
