## 二、令牌的分层（约 2 分 30 秒）

**【录屏提示】** 屏幕显示令牌的三层结构图。

企业级的 Design Token，通常分成**三层**。

**第一层，基础令牌（Primitive）。** 原始值，不带语义。

比如：

```css
--color-blue-500: #2563eb;
--color-gray-900: #111827;
--spacing-4: 1rem;
```

这些只是"调色板"和"尺寸表"，本身没有含义。

**第二层，语义令牌（Semantic）。** 给基础令牌赋予含义。

```css
--color-primary: var(--color-blue-500);
--color-text-primary: var(--color-gray-900);
--color-bg-surface: #ffffff;
```

`primary` 是"主色"，`text-primary` 是"主要文字颜色"。这些名字表达了"用途"。

**第三层，组件令牌（Component）。** 具体组件的值。

```css
--button-bg: var(--color-primary);
--button-text: #ffffff;
--button-radius: var(--radius-md);
```

**【录屏提示】** 镜头切回讲师。

**为什么要分三层？**

因为**基础令牌是"素材"，语义令牌是"用途"，组件令牌是"具体实现"**。

当品牌色要换的时候，你只需要改"基础令牌"里的 `--color-blue-500`。所有引用它的语义令牌自动更新，所有组件自动更新。

**如果只有一层**，你就得满项目找"哪里用了这个蓝色"，改起来非常痛苦。

## 三、语义令牌的命名（约 2 分 30 秒）

**【录屏提示】** 屏幕显示命名规范。

语义令牌的命名，有几个原则。

**第一，用"用途"命名，不用"外观"命名。**

不要写 `--color-blue`，要写 `--color-primary`。

因为如果哪天品牌色改成红色，`--color-blue` 就荒谬了，而 `--color-primary` 依然正确。

**第二，用"角色"区分。**

```css
--color-text-primary: #111827;      /* 主要文字 */
--color-text-secondary: #6b7280;    /* 次要文字 */
--color-text-muted: #9ca3af;        /* 弱化文字 */
--color-text-inverse: #ffffff;      /* 反色文字 */
```

不是"深灰、中灰、浅灰"，而是"主要、次要、弱化"。

**第三，用"层级"区分背景。**

```css
--color-bg-base: #ffffff;      /* 页面底色 */
--color-bg-surface: #f9fafb;   /* 卡片/区块 */
--color-bg-elevated: #ffffff;  /* 浮层 */
```

**"base / surface / elevated"** 是设计系统里的常见层级词汇。

**【录屏提示】** 镜头拉近。

**命名规范的核心思想是：让代码表达"意图"，而不是"外观"。**

**这样当设计变化时，代码不用改。** 这是专业设计系统和"随手写颜色"的本质区别。

## 四、在 Tailwind V4 里落地（约 3 分钟）

好，我们看看怎么在 V4 里落地这套体系。

**【录屏提示】** 打开 `theme.css`，写完整令牌。

```css
@theme {
  /* ============ 第一层：基础令牌 ============ */
  --color-blue-50: #eff6ff;
  --color-blue-100: #dbeafe;
  --color-blue-500: #2563eb;
  --color-blue-600: #1d4ed8;
  --color-blue-700: #1e40af;

  --color-gray-50: #f9fafb;
  --color-gray-100: #f3f4f6;
  --color-gray-500: #6b7280;
  --color-gray-900: #111827;

  /* ============ 第二层：语义令牌 ============ */
  --color-primary: var(--color-blue-500);
  --color-primary-hover: var(--color-blue-600);

  --color-text-primary: var(--color-gray-900);
  --color-text-secondary: var(--color-gray-500);
  --color-text-inverse: #ffffff;

  --color-bg-base: #ffffff;
  --color-bg-surface: var(--color-gray-50);

  --color-border-default: var(--color-gray-100);
}
```

**【录屏提示】** 边写边讲。

**关键点：语义令牌用 `var()` 引用基础令牌。** 这样就建立了"依赖关系"。

**然后 Tailwind 会自动生成对应的工具类：**

```html
<div class="bg-bg-base text-text-primary border border-border-default">
```

**【录屏提示】** 镜头拉近，语气放慢。

**注意，V4 的 `@theme` 有个细节：如果你只定义 `--color-primary`，它生成的是 `bg-primary`、`text-primary`。**

**但我上面写的 `--color-bg-base`，生成的是 `bg-bg-base`。** 有点重复。

**所以命名要精简。** 我通常的做法是：

```css
--color-primary: ...
--color-surface: ...
--color-border: ...
--color-foreground: ...
--color-muted: ...
```

**生成 `bg-surface`、`border-border`、`text-foreground`、`text-muted`。** 更简洁。

## 五、组件令牌的度（约 1 分 30 秒）

**【录屏提示】** 镜头切回讲师。

**组件令牌要不要做？我的建议是：慎做。**

**为什么？**

因为组件令牌会让"改一个组件样式"变成"改三个地方"——基础、语义、组件都要动。

**而且 Tailwind 的原子类本身就是"组件的样式"**，再抽一层组件令牌，反而增加了复杂度。

**我的做法是：只给"会跨组件复用"的值做组件令牌。**

比如"按钮的圆角"、"卡片的阴影"，这些可能被多个组件共用，值得抽。

其他的，直接在组件里用语义令牌就行。

**记住：令牌是工具，不是目的。** 不要为了"分层"而分层。
