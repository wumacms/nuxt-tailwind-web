## 二、先讲清楚：什么是设计令牌（约 1 分 30 秒）

在动手之前，我们先统一一个概念——**设计令牌**，英文叫 Design Token。

你可以把它理解成：**设计稿里那些会被反复使用的"最小设计决策"**。

比如说，品牌主色是 `#2563EB`，这个颜色在按钮上、在链接上、在图标上都会用到。那它就不应该是一个"随手写的色值"，而应该是一个**有名字的令牌**，比如 `brand-primary`。

再比如，全站正文行高是 1.7，圆角统一是 8px，卡片阴影是某一套固定的值——这些都是令牌。

那为什么企业项目一定要有令牌？

我讲三个理由：

**第一，一致性。** 没有令牌，十个页面可能出现五种不同的蓝色，因为每个人凭感觉取色。

**第二，可维护性。** 品牌色要改，有令牌的话，改一个地方，全站生效。

**第三，协作效率。** 设计师和开发说的是一套语言。设计师说"用主色"，开发知道就是 `brand-primary`，不用来回对色值。

所以在 Tailwind V4 里，`@theme` 就是**承载这套令牌的地方**。

**【录屏提示】** 切到编辑器，新建 `assets/css/theme.css`。

## 三、`@theme` 的基本语法（约 2 分钟）

好，我们打开代码。我新建一个文件，叫 `assets/css/theme.css`。

`@theme` 的写法非常直观，它本质上就是**定义 CSS 变量**，只不过用了 Tailwind 规定的命名前缀。

我写一个最简单的例子：

```css
@import "tailwindcss";

@theme {
  --color-brand-500: #2563eb;
}
```

**【录屏提示】** 边写边讲解，写完后停顿。

这里有几个点要讲清楚。

**第一，`@theme` 必须配合 `@import "tailwindcss"` 使用。** 你可以写在同一个文件里，也可以分开。我个人的习惯是——把 `@import` 放在入口文件 `main.css`，把 `@theme` 单独放一个 `theme.css`，然后在 `main.css` 里 `@import` 进来。这样结构更清晰。

**第二，命名是有规则的。** 你看 `--color-brand-500`，这个 `--color-` 前缀是 Tailwind 规定的，意思是"我定义的是一个颜色令牌"。后面的 `brand-500` 就是它的名字。

一旦你这样定义了，Tailwind 就会**自动生成对应的工具类**。也就是说，我现在可以直接在模板里写 `bg-brand-500`、`text-brand-500`、`border-brand-500`——不需要任何额外配置。

**第三，这一点很关键。** 你定义的令牌，**会覆盖 Tailwind 的默认值，或者作为新值加入**。比如你定义了 `--color-brand-500`，那 `bg-brand-500` 就能用了，同时 Tailwind 原本的 `bg-blue-500` 依然存在。

**【录屏提示】** 在页面里写一个 `bg-brand-500` 的 div，保存，浏览器实时生效。

好，你看，页面已经变蓝了。这就是 `@theme` 的威力——**定义一次，全站可用**。

## 四、完整定义一套企业令牌（约 4 分钟）

好，基础知识讲完，我们来干正事。现在看设计稿。

**【录屏提示】** 切到 Figma，逐项圈出标注。

设计稿里，我们的企业站有这些设计决策：

- **品牌色**：主色是一套蓝色，从浅到深有 9 个梯度；还有一个强调色，是橙色。
- **中性色**：灰阶，用于文字、边框、背景。
- **字体**：中文用系统字体栈，英文用 Inter。
- **圆角**：小元素 6px，卡片 12px，大容器 20px。
- **阴影**：卡片有一层柔和的阴影。
- **间距**：基于 4px 的倍数。

好，我们一项一项来写。

**【录屏提示】** 在 `theme.css` 中逐段书写，每写一段切浏览器验证。

**颜色部分：**

```css
@theme {
  /* 品牌色 */
  --color-brand-50: #eff6ff;
  --color-brand-100: #dbeafe;
  --color-brand-200: #bfdbfe;
  --color-brand-300: #93c5fd;
  --color-brand-400: #60a5fa;
  --color-brand-500: #2563eb;
  --color-brand-600: #1d4ed8;
  --color-brand-700: #1e40af;
  --color-brand-800: #1e3a8a;
  --color-brand-900: #1e3a8a;

  /* 强调色 */
  --color-accent-500: #f97316;
  --color-accent-600: #ea580c;
}
```

这里我讲一个**设计思想**。为什么品牌色要定义 9 个梯度，而不是一个颜色？

因为在真实界面里，同一个品牌色会出现在不同场景：hover 时要深一点，禁用时要浅一点，浅色背景要淡一点。**如果你只有一个色值，就会到处硬编码，最后失控。**

梯度化，是专业设计系统的基本功。

**字体部分：**

```css
  --font-sans: "Inter", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif;
  --font-display: "Inter", "PingFang SC", system-ui, sans-serif;
```

`--font-*` 定义后，就能用 `font-sans`、`font-display` 这些类。

这里讲一下**字体栈的顺序思想**：英文在前，中文在后，系统字体兜底。这样英文用 Inter 渲染，中文自动回退到苹方或微软雅黑，跨平台观感统一。

**圆角部分：**

```css
  --radius-sm: 6px;
  --radius-md: 12px;
  --radius-lg: 20px;
```

对应 `rounded-sm`、`rounded-md`、`rounded-lg`。

**阴影部分：**

```css
  --shadow-card: 0 2px 8px rgb(0 0 0 / 0.06), 0 8px 24px rgb(0 0 0 / 0.04);
```

对应 `shadow-card`。

这里顺带说一句，Tailwind 默认的 `shadow-sm`、`shadow-md` 在企业站里往往偏重，所以我通常会**自定义一套更柔和的阴影**，让卡片看起来更精致。

**间距部分：**

```css
  --spacing: 0.25rem;
```

`--spacing` 是 V4 里比较特殊的一个令牌——它是**间距的基准单位**。你设成 `0.25rem`，那 `p-4` 就等于 `1rem`。这个一般不用改，知道它存在就行。

好，写到这里，我们的令牌体系就成型了。

**【录屏提示】** 切浏览器，打开 DevTools，指着 CSS 变量面板。

你看，所有令牌都以 CSS 变量的形式存在，可以在运行时被读取、被覆盖。这就是为什么 V4 的主题能力比 V3 更强——**它不只是构建时的配置，还是运行时的变量。**

## 五、在 Nuxt 里接入（约 1 分钟）

令牌写好了，怎么让 Nuxt 用上？

**【录屏提示】** 打开 `nuxt.config.ts`。

在 `nuxt.config.ts` 里，把入口 CSS 注入进去：

```ts
export default defineNuxtConfig({
  css: ['~/assets/css/main.css'],
})
```

然后在 `main.css` 里：

```css
@import "tailwindcss";
@import "./theme.css";
```

这样，`@theme` 就生效了。

**注意顺序**：`@import "tailwindcss"` 要在前面，`theme.css` 在后面。因为主题是**基于 Tailwind 的命名规则去扩展**的。
