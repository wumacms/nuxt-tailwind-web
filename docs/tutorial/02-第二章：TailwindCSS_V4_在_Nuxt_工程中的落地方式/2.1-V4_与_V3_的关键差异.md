# 2.1-V4_与_V3_的关键差异

**【录屏提示】** 开场：讲师出镜，背景为 V3 与 V4 两版配置代码对比。

---

## 一、开场白（约 30 秒）

好，欢迎来到第二章。

从这一章开始，我们进入整门课**最核心的部分**——TailwindCSS V4 在 Nuxt 工程里到底怎么落地。

那第一件事，我们得先把 V4 和 V3 的差异搞清楚。因为现在网上的资料，**大部分还是 V3 时代的**。你跟着搜到的教程做，很可能踩坑。

这一节，我不讲 V4 的所有新特性，只讲**工程里真正会遇到的差异点**。

**【录屏提示】** 切到编辑器，左右分屏显示 V3 和 V4 的配置。

---

## 二、最大变化：配置从 JS 搬到 CSS（约 3 分钟）

第一个、也是最重要的差异：**配置文件没了。**

**【录屏提示】** 屏幕显示 V3 的 `tailwind.config.js`。

你看这是 V3 的典型配置。一个 `tailwind.config.js`，里面写 `content`、`theme`、`plugins`。旁边还有一个 `postcss.config.js`。

**【录屏提示】** 切到 V4 的目录，展示没有这两个文件。

而 V4 呢？**这两个文件都不需要了。**

配置去哪了？**全部进了 CSS。**

我们看 V4 的写法：

```css
@import "tailwindcss";

@theme {
  --color-brand-500: #2563eb;
}
```

就这两行，替代了原来的 `tailwind.config.js`。

**【录屏提示】** 镜头拉近，语气放慢。

这个变化看起来简单，但意义很大。我讲两点。

**第一，配置变成了 CSS 变量。** 这意味着它可以在**运行时被读取和修改**。V3 的配置是构建时的，一旦打包就固定了。V4 的令牌是 CSS 变量，你可以在浏览器里动态改。

**第二，配置和样式在同一个地方。** 你写 `@theme` 的时候，旁边就是你的样式规则，不用在 JS 和 CSS 之间来回跳。

---

## 三、`content` 字段的消失（约 2 分钟）

第二个差异：**`content` 字段没了。**

**【录屏提示】** 屏幕显示 V3 的 content 配置。

V3 时代，你必须手动告诉 Tailwind："去哪些文件里扫描类名"。比如：

```js
content: [
  './components/**/*.{vue,js,ts}',
  './pages/**/*.vue',
]
```

如果你漏配了某个目录，那个目录里的类名就**不会被生成**，样式就丢了。这是 V3 的高频坑。

**【录屏提示】** 切到 V4 的写法。

V4 呢？**自动检测。** 它会自己扫描项目里的文件，找到所有用到的类名。你不需要配 `content`。

**【录屏提示】** 镜头拉近，语气加重。

但是——**这里有个重要的边界要注意**。

自动检测是基于**文件扫描**的。如果你把类名写在**字符串拼接**里，比如：

```js
const cls = `text-${color}-500`
```

**Tailwind 扫不到这个类名。** 因为它在源码里看到的是 `text-${color}-500`，不是 `text-red-500`。

这个坑 V3 和 V4 都有，但 V4 因为"自动检测"给人的错觉，反而更容易踩。我们 2.3 节会专门讲怎么解决。

---

## 四、新增的指令：`@theme`、`@utility`、`@variant`（约 2 分 30 秒）

第三个差异：**一批新的 CSS 指令。**

**【录屏提示】** 屏幕逐个显示三个指令。

**`@theme`** —— 定义设计令牌。对应 V3 的 `theme.extend`。

**`@utility`** —— 定义自定义工具类。对应 V3 的 `plugin` 里的 `addUtilities`。

**`@variant`** —— 定义自定义变体。对应 V3 的 `addVariant`。

**【录屏提示】** 切到代码，演示 `@utility`。

我举个 `@utility` 的例子：

```css
@utility content-auto {
  content-visibility: auto;
}
```

写完之后，你就能用 `content-auto` 这个类了。比 V3 写插件简单太多。

**【录屏提示】** 镜头切回讲师。

这三个指令，把我们**扩展 Tailwind 的方式**从 JS 搬到了 CSS。这是 V4 的核心哲学——**CSS-first**。

---

## 五、默认值的调整（约 1 分钟）

第四个差异：**一些默认值变了。**

**【录屏提示】** 屏幕显示变化清单。

我列几个工程里会遇到的：

**默认边框颜色变了。** V3 里 `border` 默认是灰色 `gray-200`，V4 里默认是 `currentColor`。这意味着你写 `border` 不加颜色，它会**跟着文字颜色走**。这个变化很多人第一次遇到会懵。

**默认圆角命名变了。** V3 的 `rounded` 变成了 V4 的 `rounded-sm`，整体往后挪了一档。

**默认阴影命名也变了。** 同理。

**【录屏提示】** 镜头拉近。

**所以从 V3 迁移到 V4，最麻烦的不是语法，是这些"默认值"的细微变化。** 建议你迁移时，重点检查边框、圆角、阴影这三块。

---

## 六、插件生态（约 1 分钟）

第五个差异：**插件生态。**

**【录屏提示】** 屏幕显示官方插件列表。

V4 目前官方提供了一些插件，比如 `@tailwindcss/typography`、`@tailwindcss/forms`。但**很多第三方插件还没跟上 V4**。

**【录屏提示】** 镜头切回讲师。

所以如果你从 V3 迁移，**第一件事是检查你用的插件是否支持 V4**。如果没支持，要么等，要么自己用 `@utility` 重写。

我们课程里会用到 `typography`，这个官方是支持的。

---

## 七、小结与作业（约 30 秒）

好，这一节我们讲了 V4 和 V3 的五个关键差异：

**第一**，配置从 JS 搬到 CSS，`tailwind.config.js` 和 `postcss.config.js` 都不需要了。

**第二**，`content` 字段消失，改为自动检测，但动态类名依然是坑。

**第三**，新增 `@theme`、`@utility`、`@variant` 三个指令。

**第四**，默认值有调整，重点是边框、圆角、阴影。

**第五**，插件生态还在追赶。

作业：**如果你有 V3 项目，试着迁移一个小页面到 V4，感受一下差异。**
