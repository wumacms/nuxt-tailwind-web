# 2.3-在_Nuxt_组件中组织_Tailwind_类名

**【录屏提示】** 开场：讲师出镜，背景为一段 Vue 组件的 template。

---

## 一、开场白（约 30 秒）

好，欢迎回来。

这一节，我们讲一个**看起来简单、其实很容易踩坑**的话题——**在 Nuxt 组件里怎么组织 Tailwind 类名**。

你可能会想："类名不就写在 `class` 里吗，有什么好讲的？"

问题就出在"动态"上。当你需要根据状态切换样式时，怎么写才是对的？这里面有个**Tailwind 最大的坑**，我见过太多人栽在这。

这一节，我们把它讲透。

---

## 二、静态类名：最基础的写法（约 1 分 30 秒）

我们先从最简单的开始。

**【录屏提示】** 打开一个 `.vue` 文件，写模板。

```vue
<template>
  <div class="p-4 bg-white rounded-md shadow-card">
    <h2 class="text-lg font-semibold text-gray-900">标题</h2>
    <p class="mt-2 text-sm text-gray-600">描述文字</p>
  </div>
</template>
```

这就是最基础的静态类名。Tailwind 扫描源码时，会**原样看到** `p-4`、`bg-white`、`rounded-md` 这些字符串，然后生成对应的 CSS。

**【录屏提示】** 镜头切回讲师。

**静态类名没有任何坑。** 你写什么，它就生成什么。问题出在动态场景。

---

## 三、动态类名：`v-bind` 与 `:class`（约 2 分 30 秒）

好，我们来看动态的场景。

**【录屏提示】** 在模板里写一个条件样式。

假设我们有个卡片，选中时边框变蓝：

```vue
<template>
  <div
    class="p-4 bg-white rounded-md border-2"
    :class="selected ? 'border-brand-500' : 'border-transparent'"
  >
    内容
  </div>
</template>
```

注意这里用了 `:class`，值是**两个完整的、字面量的类名字符串**。

**【录屏提示】** 镜头拉近，语气加重。

**这种写法是安全的。** 因为 Tailwind 在源码里能**看到** `border-brand-500` 和 `border-transparent` 这两个完整的字符串。它会生成对应的 CSS。

那 Vue 的 `:class` 还支持**对象语法**：

```vue
<div :class="{ 'border-brand-500': selected, 'border-transparent': !selected }">
```

**这也是安全的。** 因为对象的 key 是完整的字面量字符串。

还支持**数组语法**：

```vue
<div :class="['p-4', selected && 'border-brand-500']">
```

**同样安全。** 因为数组里的每个元素都是完整字符串。

**【录屏提示】** 镜头切回讲师。

**记住一个原则：只要类名以"完整字符串"的形式出现在源码里，Tailwind 就能扫到。**

---

## 四、危险的动态拼接（约 2 分 30 秒）

好，现在我们来看**最危险**的写法。

**【录屏提示】** 写一段拼接代码。

```vue
<script setup>
const props = defineProps<{ color: 'red' | 'blue' | 'green' }>()
const colorClass = `text-${props.color}-500`
</script>

<template>
  <p :class="colorClass">彩色文字</p>
</template>
```

这段代码，**运行时是对的**。`colorClass` 会计算出 `text-red-500`，浏览器应用上去，文字确实变红。

**但是——**

**【录屏提示】** 切到构建产物，搜索 `text-red-500`。

你在打包后的 CSS 里，**找不到 `text-red-500` 这个类**。

为什么？因为 Tailwind 扫描源码时，看到的字符串是 `text-${props.color}-500`。它不知道 `props.color` 运行时是什么，所以**无法生成对应的类**。

结果就是：**开发环境可能看起来是对的（因为热更新缓存），但生产环境样式丢失。**

**【录屏提示】** 镜头拉近，语气严肃。

这是 Tailwind 项目**最经典的生产事故**。而且它很隐蔽——本地开发好好的，上线就崩。

---

## 五、解决方案（约 2 分 30 秒）

那怎么解决？我给你**三个方案**，按推荐程度排序。

**【录屏提示】** 屏幕显示三个方案。

**方案一：用完整的类名映射表。** 这是我最推荐的。

```ts
const colorMap = {
  red: 'text-red-500',
  blue: 'text-blue-500',
  green: 'text-green-500',
} as const

const colorClass = computed(() => colorMap[props.color])
```

你看，`text-red-500` 这些**完整的字符串，全都出现在源码里**。Tailwind 能扫到，能生成。运行时再根据 props 取值。

这个方案的好处是：**类型安全 + Tailwind 友好**。用 `as const` 还能让 TS 推断出联合类型。

**方案二：用 `safelist` 机制。**

V4 里你可以用 `@source inline()` 指令，强制 Tailwind 生成某些类：

```css
@source inline("text-red-500 text-blue-500 text-green-500");
```

但说实话，这个方案**不推荐**，因为你要手动维护列表，容易漏。

**方案三：用 CSS 变量。**

```vue
<p :style="{ color: `var(--color-${props.color}-500)` }">
```

因为 V4 的令牌就是 CSS 变量，你可以直接用。但这个方案**只适用于颜色**，其他属性不好用。

**【录屏提示】** 镜头切回讲师。

**总结：优先用方案一，类名映射表。** 它是显式的、类型安全的、可维护的。

## 六、一个实用的组织习惯（约 1 分钟）

最后，我分享一个**工程习惯**。

**【录屏提示】** 打开一个组件的 script 部分。

对于有多个状态变体的组件，我习惯把**类名映射表抽到 script 顶部**，用一个对象管理：

```ts
const variants = {
  size: {
    sm: 'px-3 py-1 text-sm',
    md: 'px-4 py-2 text-base',
    lg: 'px-6 py-3 text-lg',
  },
  color: {
    primary: 'bg-brand-500 text-white',
    secondary: 'bg-gray-100 text-gray-900',
  },
} as const
```

然后在模板里用 `:class="[variants.size[size], variants.color[color]]"`。

这样做的好处是：**样式逻辑集中在一处，模板干净，改起来方便，而且 Tailwind 全部能扫到。**

我们第四章做按钮组件时，会大量用这个模式。

## 七、小结与作业（约 30 秒）

好，这一节我们讲了：

**第一**，静态类名，安全。

**第二**，动态类名用完整字符串（`v-bind`、对象、数组），安全。

**第三**，动态拼接（模板字符串），**危险**，生产环境会丢样式。

**第四**，三个解决方案，推荐类名映射表。

**第五**，把变体类名抽到 script 里的组织习惯。

作业：**检查你现有项目里，有没有用模板字符串拼类名的地方，改成映射表。**
