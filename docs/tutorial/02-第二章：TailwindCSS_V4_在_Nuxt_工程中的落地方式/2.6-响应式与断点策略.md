# 2.6-响应式与断点策略

**【录屏提示】** 开场：讲师出镜，背景为不同屏幕尺寸的设备。

---

## 一、开场白（约 30 秒）

好，欢迎回来。

这一节我们讲**响应式**。

企业官网有个特点：**用户可能在手机、平板、电脑上访问**。所以响应式不是"加分项"，是"必选项"。

Tailwind 的响应式写法很简洁，但**简洁不等于简单**。用错了，会出现"桌面端好看、手机端崩"的问题。

这一节，我们讲清楚**移动优先的思维方式**，以及企业站的断点策略。

---

## 二、移动优先：思维方式的转变（约 3 分钟）

先讲最重要的一点：**移动优先。**

**【录屏提示】** 屏幕显示一段错误写法和正确写法对比。

什么叫移动优先？我举个例子。

你要做一个卡片列表：手机上一列，平板两列，桌面三列。

**很多人第一反应是这样写：**

```html
<div class="grid grid-cols-3 md:grid-cols-2 sm:grid-cols-1">
```

这个写法**是错的**。它读起来是"默认三列，中等屏幕两列，小屏幕一列"。

但 Tailwind 的断点是**向上生效**的。`md:` 的意思是"中等屏幕及以上"。所以这个写法在桌面是大屏三列，到了中等屏幕变成两列，再小还是一列——但**手机（小于 sm）会保持三列**，因为它没有被任何断点覆盖。

**正确的写法是移动优先：**

```html
<div class="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3">
```

读法："默认一列，中等屏幕及以上两列，大屏幕及以上三列。"

**【录屏提示】** 镜头拉近，语气加重。

**移动优先的核心是：先写手机样式，再用断点"往上加"。** 不要写"从桌面往下减"。

这个思维转变很重要。因为**大部分企业站的流量来自手机**，先保证手机体验，再增强大屏。

---

## 三、默认断点（约 1 分 30 秒）

好，讲一下 Tailwind 的默认断点。

**【录屏提示】** 屏幕显示断点表。

| 断点   | 最小宽度 | 典型设备        |
| ------ | -------- | --------------- |
| （无） | 0        | 手机            |
| `sm`   | 640px    | 大手机 / 小平板 |
| `md`   | 768px    | 平板            |
| `lg`   | 1024px   | 小笔记本        |
| `xl`   | 1280px   | 桌面            |
| `2xl`  | 1536px   | 大桌面          |

这些默认值，**一般够用**。企业站通常只需要用到 `md`、`lg`、`xl` 三个。

**【录屏提示】** 镜头切回讲师。

如果你要改断点值，可以在 `@theme` 里覆盖：

```css
@theme {
  --breakpoint-md: 800px;
}
```

但我的建议是：**除非设计稿有明确要求，否则别改。** 用默认值，团队认知成本最低。

---

## 四、`max-*` 变体：向下生效（约 1 分 30 秒）

好，除了"向上生效"的断点，V4 还支持"向下生效"的 `max-*` 变体。

**【录屏提示】** 屏幕显示 `max-*` 用法。

```html
<div class="max-md:hidden">桌面端显示</div>
```

`max-md:hidden` 的意思是"中等屏幕以下隐藏"。等价于"平板及以上显示"。

**什么时候用 `max-*`？**

当你要**为小屏幕做特殊处理**时。比如"手机端隐藏侧边栏"：

```html
<aside class="hidden md:block">侧边栏</aside>
```

用 `md:block` 也可以，但 `max-md:hidden` 读起来更直接。

**【录屏提示】** 镜头拉近。

**但我要提醒你**：`max-*` 和 `min-*`（也就是普通断点）**混用容易乱**。企业项目里，我建议**以移动优先的向上断点为主**，`max-*` 只在确实需要时用。

---

## 五、容器查询：组件级响应式（约 1 分 30 秒）

好，讲一个 V4 里的新能力——**容器查询**。

**【录屏提示】** 屏幕显示传统响应式 vs 容器查询的区别。

传统的断点，是**基于视口宽度**的。但有时候，你希望组件**根据自己容器的宽度**来响应，而不是视口。

举个例子：一个卡片组件，放在主内容区时是宽的，放在侧边栏时是窄的。用视口断点做不到，因为视口没变，只是容器变了。

**容器查询解决这个问题：**

```html
<div class="@container">
  <div class="@md:flex @md:gap-4">
    卡片内容
  </div>
</div>
```

`@container` 标记一个容器，`@md:` 表示"容器宽度达到 md 时"。

**【录屏提示】** 镜头切回讲师。

**容器查询是组件库的利器。** 它让组件真正"自适应"自己的空间，而不是假设自己在页面中间。

企业站里，卡片、列表项、侧边栏内容都适合用容器查询。

---

## 六、企业站的断点策略（约 1 分钟）

最后，我给你一个**实战策略**。

**【录屏提示】** 屏幕显示策略建议。

**第一，断点只用三个：`md`、`lg`、`xl`。** 太多断点维护成本高。

**第二，先做移动端，再做桌面端。** 不要先做桌面再"适配"手机。

**第三，用布局组件承载断点。** 比如 `<AppContainer>` 里处理宽度，页面里就不重复写断点。

**第四，复杂组件用容器查询。** 让组件自适应容器，而不是依赖视口。

**第五，测试要用真机。** 浏览器缩放模拟不如真机准，尤其是触摸交互。
