# 2.4-抽取可复用样式：@apply_vs_组件化

**【录屏提示】** 开场：讲师出镜，背景为"复用"两个字。

---

## 一、开场白（约 30 秒）

好，欢迎回来。

这一节我们聊一个**哲学问题**——样式怎么复用？

Tailwind 的原子类，天生就有"重复"的问题。同一个按钮样式，你可能在十个地方写了一遍。那该怎么办？抽出来啊。

但"抽"有很多种方式：`@apply`、`@utility`、抽组件、CSS 变量……到底用哪个？

这一节，我给你一个**决策树**。

---

## 二、为什么这是个问题（约 1 分 30 秒）

先说清楚问题的本质。

**【录屏提示】** 屏幕显示三段重复的按钮类名。

假设你有三个地方都有主按钮：

```html
<button class="px-4 py-2 bg-brand-500 text-white rounded-md hover:bg-brand-600">
```

```html
<button class="px-4 py-2 bg-brand-500 text-white rounded-md hover:bg-brand-600">
```

```html
<button class="px-4 py-2 bg-brand-500 text-white rounded-md hover:bg-brand-600">
```

**重复了三次。** 品牌色要改，你得改三处。这就是"复用"要解决的问题。

**【录屏提示】** 镜头切回讲师。

但是，**过度复用也是问题**。有些人一看到重复就抽，结果抽出一堆只用一次的东西，反而增加了理解成本。

所以关键不是"要不要抽"，而是"**用什么方式抽、抽到什么程度**"。

---

## 三、四种复用方式（约 5 分钟）

我给你四种方式，逐个讲。

**【录屏提示】** 屏幕显示四种方式的对比表。

### 方式一：`@apply` —— 把原子类打包成一个类

```css
@layer components {
  .btn-primary {
    @apply px-4 py-2 bg-brand-500 text-white rounded-md hover:bg-brand-600;
  }
}
```

然后模板里就写 `<button class="btn-primary">`。

**优点**：模板简洁，改动集中。

**缺点**：**它退回了传统 CSS 的思路。** 你写了一个语义化的类名，但失去了原子类的"就地可见"优势。别人看 `<button class="btn-primary">`，不知道它到底长什么样，得跳到 CSS 文件去看。

**【录屏提示】** 镜头拉近，语气加重。

**`@apply` 最大的问题是：它容易被滥用。** 一旦你开始抽 `.card`、`.section`、`.text-title`，你的项目就变成了"用 Tailwind 语法写传统 CSS"。Tailwind 的优势全没了。

我的建议是：**`@apply` 只在一种情况下用——你要覆盖第三方库的样式，或者写一些无法用组件封装的全局类。**

### 方式二：`@utility` —— 定义自定义工具类

```css
@utility btn {
  padding: theme(--spacing-2) theme(--spacing-4);
  /* ... */
}
```

这是 V4 的新方式。它和 `@apply` 的区别是：`@utility` 定义的是一个**可以被变体修饰的工具类**。比如你可以写 `hover:btn`、`md:btn`。

**但它同样有"语义化类名"的问题。** 而且写法更底层，一般不用。

**什么时候用？** 当你需要一个**可以响应变体**的自定义工具类时。比如 `text-balance`、`content-auto` 这种。

### 方式三：抽组件 —— 最推荐

```vue
<!-- components/ui/AppButton.vue -->
<template>
  <button class="px-4 py-2 bg-brand-500 text-white rounded-md hover:bg-brand-600">
    <slot />
  </button>
</template>
```

然后 `<AppButton>提交</AppButton>`。

**优点**：

- 样式和结构封装在一起，**就地可见**；
- 可以通过 props 支持变体；
- 有类型约束；
- 符合 Vue 组件化思维。

**【录屏提示】** 镜头切回讲师，语气肯定。

**这是我 90% 情况下推荐的方案。** 只要你有一段样式会重复使用，并且它有"结构"（不只是颜色），就抽组件。

### 方式四：CSS 变量 —— 用于主题化

```css
@theme {
  --color-brand-500: #2563eb;
}
```

然后所有用到品牌色的地方，都用 `bg-brand-500`。

**这不是"样式复用"，而是"值复用"。** 它解决的是"同一个设计决策在多处使用"的问题，而不是"同一段样式结构在多处使用"。

**令牌体系本身就是一种复用。** 我们 2.2 已经做了。

---

## 四、决策树（约 2 分钟）

好，四种方式讲完，我给你一个**决策流程**。

**【录屏提示】** 屏幕显示决策树图。

**第一步：问自己，这段样式有没有"结构"？**

比如按钮，它有"按钮元素 + 内边距 + 背景色 + 圆角 + hover 效果"，这是结构。有结构，**抽组件**。

如果只是"一个颜色值在很多地方用"，那是值，**用令牌**。

**第二步：如果抽组件不合适，问自己，这个类需不需要被变体修饰？**

需要 `hover:`、`md:` 这种修饰，用 `@utility`。

不需要，用 `@apply`。

**第三步：如果都不确定，先别抽。**

**重复两三次之后，再抽也不迟。** 过早抽象比重复更糟。

---

## 五、一个实战例子（约 1 分钟）

我们举个具体例子。

**【录屏提示】** 屏幕显示两个场景。

**场景一**：主按钮出现在首页、产品页、联系页。

→ 有结构，抽成 `<AppButton variant="primary">`。

**场景二**：所有卡片都用同一个阴影。

→ 这是值，定义 `--shadow-card` 令牌，用 `shadow-card`。

**场景三**：所有 h1 标题样式一样。

→ 有结构（字号、字重、行高），抽成 `<AppHeading level="1">` 组件，或者用 `@apply` 定义一个 `.heading-1`。我**更推荐前者**。

**【录屏提示】** 镜头切回讲师。

你看，决策的核心是：**问清楚"我复用的是值还是结构"。**

---

## 六、小结与作业（约 30 秒）

好，这一节我们讲了四种复用方式：

**第一**，`@apply`，慎用，容易退化成传统 CSS。

**第二**，`@utility`，用于自定义可被变体修饰的工具类。

**第三**，抽组件，**最推荐**，符合 Vue 思维。

**第四**，CSS 变量，用于值复用，令牌体系。

**决策原则**：先问"复用值还是结构"，再问"需不需要变体"，最后"不确定就先别抽"。

作业：**审视你项目里的 `@apply` 使用，判断哪些该改成组件，哪些该保留。**
