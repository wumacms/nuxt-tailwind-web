## 二、全局样式的注入（约 2 分钟）

先讲最基础的——**怎么把样式注入 Nuxt**。

**【录屏提示】** 打开 `nuxt.config.ts`。

```ts
export default defineNuxtConfig({
  css: [
    '~/assets/css/main.css',
  ],
})
```

`css` 字段接受一个数组，可以注入多个 CSS 文件。Nuxt 会**按顺序**引入。

**【录屏提示】** 打开 `main.css`。

而 `main.css` 里，我们用 `@import` 组织：

```css
@import "tailwindcss";
@import "./theme.css";
@import "./base.css";
@import "./utilities.css";
```

**【录屏提示】** 镜头拉近，语气放慢。

这里有个**顺序原则**，我强调一下：

1. **`tailwindcss` 必须最先**，因为它是基础。
2. **`theme.css` 紧随其后**，因为它定义了令牌。
3. **`base.css` 在中间**，全局基础样式。
4. **`utilities.css` 最后**，自定义工具类。

**为什么顺序重要？** 因为 CSS 是层叠的。后面的规则会覆盖前面的。这个顺序能保证：**自定义的优先级高于 Tailwind 默认，但又不至于到处 `!important`。**

---

## 三、`base.css` 里放什么（约 1 分 30 秒）

好，我们看看 `base.css` 具体放什么。

**【录屏提示】** 打开 `base.css`，写内容。

```css
@layer base {
  html {
    -webkit-font-smoothing: antialiased;
    text-rendering: optimizeLegibility;
  }

  body {
    @apply font-sans text-gray-900 bg-white;
  }

  h1, h2, h3, h4, h5, h6 {
    @apply font-display font-semibold;
  }

  a {
    @apply text-brand-500 hover:text-brand-600 transition-colors;
  }
}
```

这里讲几个点。

**第一，用 `@layer base`。** 这让样式进入 Tailwind 的 base 层，优先级正确。**不要直接写在顶层**，否则会覆盖一切。

**第二，全局字体和颜色。** `body` 上设置 `font-sans` 和默认文字颜色，全站继承。

**第三，标题统一字重。** 所有 `h1`~`h6` 统一用 `font-display` 和 `font-semibold`，保证标题风格一致。

**第四，链接统一样式。** 全站链接的颜色和 hover 效果，集中在这里。

**【录屏提示】** 镜头切回讲师。

`base.css` 的原则是：**只放"全站统一、几乎不会单独覆盖"的样式。** 放太多，反而会跟组件样式打架。

---

## 四、`utilities.css` 里放什么（约 1 分 30 秒）

好，接着看 `utilities.css`。

**【录屏提示】** 打开 `utilities.css`，写内容。

```css
@utility text-balance {
  text-wrap: balance;
}

@utility content-auto {
  content-visibility: auto;
}

@utility scrollbar-hide {
  scrollbar-width: none;
  &::-webkit-scrollbar {
    display: none;
  }
}
```

这里用 **`@utility`** 定义自定义工具类。

**为什么用 `@utility` 而不是 `@layer utilities`？**

因为 `@utility` 定义的类，**可以被变体修饰**。比如你可以写 `md:text-balance`、`hover:scrollbar-hide`。

**【录屏提示】** 镜头拉近。

**`utilities.css` 放什么？** 放那些**"Tailwind 没提供，但你的项目需要"的小工具类**。

比如 `text-balance`（让标题换行更均匀）、`scrollbar-hide`（隐藏滚动条）、`content-auto`（性能优化）。

**不要放业务样式。** 业务样式应该在组件里。

## 五、`app.config.ts`：运行时配置（约 2 分钟）

好，接下来讲一个 Nuxt 特有的东西——**`app.config.ts`**。

**【录屏提示】** 新建 `app.config.ts`，写内容。

```ts
export default defineAppConfig({
  site: {
    name: '某某科技',
    description: '专业的企业解决方案提供商',
    logo: '/logo.svg',
  },
  theme: {
    primary: 'brand',
    radius: 'md',
  },
})
```

**【录屏提示】** 镜头拉近，语气加重。

**这个文件的关键特性是：它在运行时可用，而且可以响应式访问。**

什么意思？

`nuxt.config.ts` 是**构建时配置**——它在打包时就固定了，运行时改不了。

`app.config.ts` 是**运行时配置**——它会被打包进应用，但可以在运行时读取，甚至通过 `useAppConfig()` 动态修改。

**【录屏提示】** 在组件里演示。

```vue
<script setup lang="ts">
const appConfig = useAppConfig()
</script>

<template>
  <h1>{{ appConfig.site.name }}</h1>
</template>
```

你看，站点名、描述、logo 这些**不涉及敏感信息、又可能变化**的配置，就适合放这里。

**什么时候用 `app.config.ts`？**

- 站点元信息（名称、描述）
- 主题配置（默认主题、默认圆角）
- 功能开关（是否显示某个模块）
- 社交媒体链接

**什么时候用 `nuxt.config.ts`？**

- 构建相关（vite 插件、css 注入）
- 敏感信息（API 密钥，实际用 `.env`）
- 路由规则（`routeRules`）

**【录屏提示】** 镜头切回讲师。

**核心区别：`app.config` 是"应用内容"，`nuxt.config` 是"应用配置"。** 前者可以热更新，后者不行。

## 六、环境变量（约 1 分钟）

顺带讲一下**环境变量**。

**【录屏提示】** 打开 `.env` 文件。

```bash
NUXT_PUBLIC_API_BASE=https://api.example.com
NUXT_API_SECRET=xxx
```

Nuxt 的约定是：

- **`NUXT_PUBLIC_` 开头**：客户端和服务端都能访问。
- **不加 `NUXT_PUBLIC_`**：只在服务端可访问，**不会泄漏到客户端**。

**【录屏提示】** 镜头拉近，语气严肃。

**这是安全边界。** API 密钥、数据库密码，**绝对不能加 `NUXT_PUBLIC_` 前缀**，否则会打包进客户端代码，所有人都能看到。

用的时候：

```ts
const config = useRuntimeConfig()
console.log(config.public.apiBase)  // 客户端可访问
console.log(config.apiSecret)        // 仅服务端
```
