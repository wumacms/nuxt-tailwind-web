## 二、表单设计（约 2 分 30 秒）

**【录屏提示】** 新建 `pages/contact.vue`。

```vue
<script setup lang="ts">
useSeoMeta({
  title: '联系我们 - 某某科技',
  description: '欢迎联系我们，获取专业的解决方案和报价。',
})

interface FormData {
  name: string
  email: string
  phone: string
  company: string
  message: string
}

const form = reactive<FormData>({
  name: '',
  email: '',
  phone: '',
  company: '',
  message: '',
})

const errors = reactive<Partial<Record<keyof FormData, string>>>({})
const submitting = ref(false)
const toast = useToast()

async function handleSubmit() {
  // 清空错误
  Object.keys(errors).forEach(k => delete errors[k as keyof FormData])

  // 前端校验
  if (!form.name.trim()) errors.name = '请输入姓名'
  if (!form.email.trim()) errors.email = '请输入邮箱'
  else if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(form.email)) errors.email = '邮箱格式不正确'
  if (!form.message.trim()) errors.message = '请输入留言内容'

  if (Object.keys(errors).length) return

  submitting.value = true
  try {
    await $fetch('/api/contact', {
      method: 'POST',
      body: form,
    })
    toast.success('提交成功，我们会尽快联系您')
    Object.keys(form).forEach(k => form[k as keyof FormData] = '')
  } catch (err: any) {
    toast.error(err.data?.message || '提交失败，请稍后重试')
  } finally {
    submitting.value = false
  }
}
</script>
```

**【录屏提示】** 边写边讲。

几个关键点。

**第一，`reactive` 管理表单数据。** 比多个 `ref` 干净。

**第二，`errors` 对象管理错误。** 每个字段一个错误信息。

**第三，前端校验。** 必填、格式。**但前端校验只是体验，服务端还要再校验一遍。**

**第四，`$fetch` 调用接口。** 注意这里用 `$fetch` 而不是 `useFetch`，因为这是**提交动作**，不是获取数据。

**第五，`toast` 反馈。** 复用我们 4.5 做的 Toast 系统。

**【录屏提示】** 镜头拉近，语气加重。

**`useFetch` 用于"取数据"，`$fetch` 用于"提交动作"。** 这是 Nuxt 的约定，别混用。

## 三、表单模板（约 2 分钟）

**【录屏提示】** 写模板部分。

```vue
<template>
  <div>
    <PageHero title="联系我们" subtitle="我们期待与您的合作" />

    <PageSection>
      <AppContainer size="narrow">
        <form class="space-y-5" @submit.prevent="handleSubmit">
          <div class="grid grid-cols-1 md:grid-cols-2 gap-5">
            <FormField label="姓名" required for="name" :error="errors.name">
              <AppInput id="name" v-model="form.name" placeholder="您的姓名" :error="!!errors.name" />
            </FormField>

            <FormField label="邮箱" required for="email" :error="errors.email">
              <AppInput id="email" v-model="form.email" type="email" placeholder="your@email.com" :error="!!errors.email" />
            </FormField>

            <FormField label="电话" for="phone">
              <AppInput id="phone" v-model="form.phone" type="tel" placeholder="选填" />
            </FormField>

            <FormField label="公司" for="company">
              <AppInput id="company" v-model="form.company" placeholder="选填" />
            </FormField>
          </div>

          <FormField label="留言" required for="message" :error="errors.message">
            <AppTextarea id="message" v-model="form.message" rows="6" placeholder="请描述您的需求..." :error="!!errors.message" />
          </FormField>

          <AppButton type="submit" size="lg" :loading="submitting" block>
            {{ submitting ? '提交中...' : '提交' }}
          </AppButton>
        </form>
      </AppContainer>
    </PageSection>
  </div>
</template>
```

**【录屏提示】** 镜头切回讲师。

**注意我们复用了一切**：`PageHero`、`PageSection`、`AppContainer`、`FormField`、`AppInput`、`AppTextarea`、`AppButton`。

**这就是前面四章积累的价值。** 做业务页面时，你只是在"组装"。

## 四、服务端接口（约 3 分钟）

好，接下来做**服务端接口**。

**【录屏提示】** 新建 `server/api/contact.post.ts`。

```ts
interface ContactBody {
  name: string
  email: string
  phone?: string
  company?: string
  message: string
}

export default defineEventHandler(async (event) => {
  const body = await readBody<ContactBody>(event)

  // 服务端校验
  const errors: Record<string, string> = {}

  if (!body.name?.trim()) errors.name = '姓名不能为空'
  if (!body.email?.trim()) errors.email = '邮箱不能为空'
  else if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(body.email)) errors.email = '邮箱格式不正确'
  if (!body.message?.trim()) errors.message = '留言不能为空'
  if (body.message && body.message.length > 500) errors.message = '留言不能超过 500 字'

  if (Object.keys(errors).length) {
    throw createError({
      statusCode: 400,
      statusMessage: '表单校验失败',
      data: { errors, message: '请检查表单内容' },
    })
  }

  // 这里可以：存数据库、发邮件、调 webhook
  // 演示用，打印日志
  console.log('收到联系表单：', body)

  return {
    success: true,
    message: '提交成功',
  }
})
```

**【录屏提示】** 边写边讲。

几个关键点。

**第一，文件命名 `contact.post.ts`。** 后缀 `.post` 表示只处理 POST 请求。Nuxt 会自动映射成 `/api/contact`。

**第二，`readBody`。** 读取请求体。

**第三，服务端再校验一遍。** **这一步不能省**，因为前端校验可以被绕过。**这是安全边界。**

**第四，`createError` 抛错。** 前端能通过 `err.data` 拿到详细信息。

**第五，实际业务里要接入邮件服务或数据库。** 演示用 `console.log` 代替。

**【录屏提示】** 镜头拉近，语气加重。

**服务端校验不是"重复劳动"，是"安全必需"。** 前端校验是体验优化，服务端校验是底线。**企业项目必须两个都做。**

## 五、防重复提交（约 1 分钟）

**【录屏提示】** 镜头切回讲师。

**一个容易忽略的细节：防重复提交。**

用户网络慢的时候，可能连点几次提交按钮。**解决办法是禁用按钮。**

我们的 `AppButton` 有 `loading` 属性，`submitting` 为 true 时会自动禁用。**这就是 `loading` 状态的实际价值。**

```vue
<AppButton type="submit" :loading="submitting">
  {{ submitting ? '提交中...' : '提交' }}
</AppButton>
```

**服务端也可以做限流**，比如同一 IP 一分钟只能提交一次。这个我们第八章讲。

## 六、地图嵌入（约 1 分钟）

**【录屏提示】** 屏幕显示地图组件。

联系页通常会嵌入地图。做法有两种：

**方式一，iframe 嵌入。** 高德、百度地图都提供嵌入代码。**简单，但要注意懒加载。**

```html
<iframe
  src="..."
  loading="lazy"
  class="w-full h-96 rounded-lg"
/>
```

**方式二，JS SDK。** 更灵活，但要引入外部脚本。

**【录屏提示】** 镜头切回讲师。

**企业站推荐 iframe + 懒加载。** 简单可靠，不影响首屏。

**注意隐私合规**：欧盟 GDPR 要求地图加载前需要用户同意。国内一般不需要，但要知道有这个要求。
