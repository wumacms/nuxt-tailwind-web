## 二、Nuxt 的错误处理（约 2 分钟）

**【录屏提示】** 屏幕显示 Nuxt 的错误机制。

Nuxt 的错误分两类。

**第一类，服务端错误。** 比如 500、404。通过 `createError` 抛出。

**第二类，客户端错误。** 比如路由不存在、组件渲染失败。

**【录屏提示】** 镜头切回讲师。

Nuxt 会自动捕获这些错误，然后渲染 `error.vue`。

**关键是：我们要自定义 `error.vue`。**

**默认的 error 页很朴素。** 我们把它换成品牌化的版本。

---

## 三、实现 error.vue（约 4 分钟）

**【录屏提示】** 新建 `error.vue`（在项目根目录，不是 `pages/` 里）。

```vue
<script setup lang="ts">
import type { NuxtError } from '#app'

interface Props {
  error: NuxtError
}

const props = defineProps<Props>()

const is404 = computed(() => props.error.statusCode === 404)

const title = computed(() => is404.value ? '页面走丢了' : '出了点问题')
const description = computed(() =>
  is404.value
    ? '您访问的页面不存在，可能已被移动或删除。'
    : '服务器开小差了，请稍后重试。'
)

function goHome() {
  clearError({ redirect: '/' })
}
</script>

<template>
  <div class="min-h-screen flex flex-col">
    <AppHeader />

    <main class="flex-1 flex items-center justify-center pt-16">
      <AppContainer>
        <div class="text-center py-20">
          <p class="text-8xl lg:text-9xl font-display font-bold text-brand-500">
            {{ error.statusCode }}
          </p>
          <h1 class="mt-6 text-3xl lg:text-4xl font-display font-bold text-gray-900">
            {{ title }}
          </h1>
          <p class="mt-4 text-lg text-gray-600 max-w-md mx-auto">
            {{ description }}
          </p>
          <div class="mt-10 flex flex-wrap justify-center gap-4">
            <AppButton size="lg" @click="goHome">返回首页</AppButton>
            <AppButton size="lg" variant="secondary" @click="$router.back()">
              返回上一页
            </AppButton>
          </div>
        </div>
      </AppContainer>
    </main>

    <AppFooter />
  </div>
</template>
```

**【录屏提示】** 边写边讲。

几个关键点。

**第一，`error.vue` 在项目根目录。** 不在 `pages/` 里。这是 Nuxt 的约定。

**第二，接受 `error` prop。** 类型是 `NuxtError`，包含 `statusCode`、`statusMessage`、`message`。

**第三，区分 404 和其他错误。** 404 说"页面走丢了"，500 说"服务器开小差"。**不同的错误，不同的文案。**

**第四，`clearError({ redirect: '/' })`。** 这是 Nuxt 提供的 API，清除错误状态并跳转。**不要用 `navigateTo`，因为错误状态下路由是锁的。**

**第五，复用 `AppHeader` 和 `AppFooter`。** 错误页也有完整的品牌结构。

**【录屏提示】** 镜头拉近，语气加重。

**注意 `clearError` 而不是 `navigateTo`。** 这是很多人踩的坑。错误页里直接用路由跳转会失败。

## 四、404 的设计（约 2 分钟）

**【录屏提示】** 镜头切回讲师。

我单独讲讲 404 的设计。

**好的 404 页，要包含：**

**第一，清晰的错误码。** 大大的 `404`，让人一眼知道发生了什么。

**第二，友好的文案。** 不要写"Not Found"，写"页面走丢了"。**用人话，有温度。**

**第三，明确的出路。** 至少一个"返回首页"按钮。**不要让用户无路可走。**

**第四，品牌元素。** logo、配色、插画。**让错误页也是品牌的一部分。**

**第五，可选：搜索框。** 帮助用户找到想要的内容。

**【录屏提示】** 屏幕显示优秀 404 案例。

你可以看看这些优秀案例。它们的共同点是：**把错误页当成一个"可爱的意外"来设计，而不是一个"技术故障"。**

## 五、测试错误页（约 1 分钟）

**【录屏提示】** 访问一个不存在的路由，展示错误页。

怎么测试？

**方法一，访问不存在的路由。** 比如 `/asdfasdf`，会触发 404。

**方法二，在页面里抛错。** 比如 `throw createError({ statusCode: 500 })`。

**方法三，产品详情页传不存在的 slug。** 我们 5.3 写的 `throw createError` 会触发 404。

**【录屏提示】** 镜头切回讲师。

**三种方式都要测一遍。** 确保 404 和 500 都显示正确。
